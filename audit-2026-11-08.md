## Findings and concrete fixes

### F1 — Validate the final declaration before accepting it

**MEDIUM; [CODE], [VERIFIED-SYNTHETIC].** [hooks/verdict_logger.py:213](https://github.com/sergeeey/Claude-cod-top-2026/blob/7830bab3e590707fde1abcd617fc5e93140157f6/hooks/verdict_logger.py#L213) filters values into `valid`, then returns `valid[-1]`. This is “last valid declaration wins,” although the existing test at `tests/test_verdict_logger.py:436` describes the last declaration winning.

```text
SKEPTIC-VERDICT: CONFIRMED-REAL
SKEPTIC-VERDICT: FALSIFIED because control failed
SKEPTIC-EVIDENCE: VERIFIED-REAL
SKEPTIC-DATA: results.csv
```

Actual `main()` wrote `verdict=CONFIRMED-REAL` and `evidence_claimed=VERIFIED-REAL`. The second declaration is invalid under the exact grammar; safe behavior is no accepted verdict, not revival of the earlier positive value. Controls: the invalid declaration alone produces no record; replacing it with exact `FALSIFIED` correctly records FALSIFIED. Base recognizes no skeptic footer. This defect is introduced by the new feature.

**Fix:** Select the last declaration first, then validate it, or require exactly one declaration. Add valid→invalid, invalid→valid, conflicting-duplicate and valid-single controls. Real occurrence frequency is **[NEEDS-REAL-DATA]**.

### F2 — Exclude footers inside an open code fence

**MEDIUM; [CODE], [VERIFIED-SYNTHETIC].** [hooks/verdict_logger.py:109](https://github.com/sergeeey/Claude-cod-top-2026/blob/7830bab3e590707fde1abcd617fc5e93140157f6/hooks/verdict_logger.py#L109) scans backwards for contiguous footer lines without tracking Markdown fence context. `tests/test_verdict_logger.py:520` covers only a closed fence.

An `Example only:` line followed by an opening triple-backtick fence and a valid CONFIRMED-REAL footer without a closing fence is accepted. Actual logging with synthetic metadata explicitly marking the run `truncated` still wrote CONFIRMED-REAL / VERIFIED-REAL. Adding the closing fence suppresses the record. Outcome metadata was injected by the probe, not recovered from a real truncated transcript.

**Fix:** Track fence context before accepting the terminal block, including unclosed backtick and tilde fences. Keep partial-run telemetry if useful, but do not interpret example text as an issued verdict. Add closed/unclosed fence, plain-footer and truncated-message controls. Scientific tags remain outside `false_pass_rate.PASS_VERDICTS`, limiting immediate metric impact. No production false confirmation was established.

### F3 — Use declared agent identity to select the verdict

**MEDIUM; [CODE], [VERIFIED-SYNTHETIC]; pre-existing.** [hooks/verdict_logger.py:184](https://github.com/sergeeey/Claude-cod-top-2026/blob/7830bab3e590707fde1abcd617fc5e93140157f6/hooks/verdict_logger.py#L184) returns upon finding any reviewer-format verdict. `_worst()` never compares it with security-format verdicts. At line 378, identity renames the agent without selecting its corresponding verdict.

Input `Quoted reviewer:\nVERDICT: LGTM\nSecurity finding remains.\nVerdict: BLOCK\n` extracts reviewer/LGTM in **both base and target**. Target `main()` with `agent_type=security-guard` writes security-guard/LGTM. `scripts/false_pass_rate.py:204` counts LGTM as pass-class regardless of agent. Same-label LGTM followed by BLOCK is correctly handled by the new target, so that improvement is real.

**Fix:** Choose the declared agent's grammar before extraction. For identity-free legacy records, define a conservative rule across both label families. Test conflicts with and without declared identity. This is a remaining defect in the behavior the PR claims to harden, not a newly introduced regression.

Comments around line 355 treat top-level event identity as hypothetical.
