## 1. Почему этот навык

| Факт | Источник |
|---|---|
| 21 вызов за 60 дней (2026-11-24 скан) | memory `project_skill_usage_scan_20261124` [MEMORY] |
| maturity `described`, kind `verifier` | `skills/registry.yaml` [VERIFIED] |
| Нет папки `benchmarks/deletion-test/` (есть у 14 других навыков) | `ls benchmarks/` [VERIFIED] |
| Выход — классификация модулей (DEAD / DUPLICATE / GOD / HEALTHY / CRITICAL), то есть ответ проверяем на эталонной структуре | `SKILL.md` [CODE] |
| В отчёте по библиотеке «безопасное удаление навыков» помечено как недостаточное. Сам deletion-test — аудит архитектуры, а не процедура удаления навыков | пакет от другой сессии [MEMORY] |

Скан использования считает только вызовы инструмента Skill. Вызовы через хуки и slash-команды
не видны, поэтому 21 — нижняя граница, а не мера ценности.

## 2. Вопрос и тип утверждения

Вопрос: правильно ли навык относит модули к классам на репозитории с заранее известной
структурой, и не отмечает ли он используемый модуль как мёртвый?

Тип: предиктивный (EstimandOps L0). Причинных выводов из результата не делаем.

Эталон: синтетический репозиторий с размеченными модулями. По правилу maturity для verifier-навыков
синтетический эталон допустим, если он построен с известным ответом; результат помечается
`[VERIFIED-SYNTHETIC]` и не переносится на реальные проекты без отдельной проверки.

## 3. Три режима (не два)

| Режим | Что это |
|---|---|
| V0 | текущий `skills/extensions/deletion-test/SKILL.md` (исходный) |
| V1 | кандидат (пока не существует; создаётся только после согласования) |
| N | та же задача без навыка, обычным промптом |

Сравнивать V1 с V0 недостаточно: без N нельзя сказать, что навык вообще даёт пользу.

## 4. Метрики (фиксируются до запуска)

| Метрика | Зачем |
|---|---|
| Ложный DEAD: используемый модуль помечен как мёртвый | **главная ошибка**, удаление рабочего кода |
| Recall CRITICAL | не пропущен ли критичный модуль |
| Точность по классам (macro-F1) | общее качество классификации |
| Доля вердиктов с ссылкой на grep-доказательство (файл:строка) | проверяемость |
| Стоимость: токены и время на прогон | эффективность затрат |
| Разброс между повторами одного режима | нестабильность модели |

Порог «улучшено» задаётся до запуска. Предлагаю: ложный DEAD у V1 не выше, чем у V0, и
macro-F1 выше не менее чем на 0.10 при одинаковом числе повторов. Цифры — предложение, согласовать.

## 5. Эталонный репозиторий (состав, без ответов в git)

Ответы (ground truth) не коммитятся даже в локальную ветку: правило из памяти
`feedback_blind_eval_answers_outside_git`. Ключ хранится вне репозитория, например в
`~/.claude/state/skill-pilot/`.

Состав фикстуры (предложение):

Ожидаемые классы для каждого модуля в git не записаны: они лежат в ключе вне репозитория.
Здесь только типы структур, которые фикстура моделирует (без ответов):

| Тип структуры | Что моделирует |
|---|---|
| Модуль без импортёров | кандидат на удаление |
| Модуль с двумя копиями логики | кандидат на дубликат |
| Модуль с высоким fan-in и несвязанными обязанностями | кандидат на «божественный» модуль |
| Модуль с большим fan-in без дублёра | кандидат на критичный |
| Модуль с одним потребителем и одной обязанностью | обычный случай |
| Модуль, используемый только через `importlib` | статический grep его не видит |

Негативный контроль: отдельный репозиторий, где все модули здоровы. Навык не должен находить DEAD.

## 6. Ограничения (что не доказываем)

- Число прогонов мало, поэтому минимальный обнаруживаемый эффект (MDE) большой. Его надо
  записать вместе с результатом: `n`, `alpha`, `power`, `MDE`, `MCID`.
- Синтетический эталон не говорит, как навык работает на реальных проектах.
- Один прогон модели — не измерение. Нужны повторы.

## 7. Что не считается улучшением

- Более длинная или более убедительная инструкция.
- Исправление формата, тегов и ссылок (это техобслуживание, не рост качества).
- Переименование или слияние с другими навыками.

## 8. Что требует отдельного согласования

| Действие | Почему |
|---|---|
| Запуск любого прогона модели (V0, V1, N, повторы) | платный эксперимент |
| Создание V1 как изменения SKILL.md | это предложение, не отдельный шаг без вашего решения |
| Сборка фикстуры и ключа | офлайн, бесплатно, но ключ держим вне git |
| Повышение maturity до `dogfooded` | только с артефактом, который проверяет CI, и реальным прогоном |
