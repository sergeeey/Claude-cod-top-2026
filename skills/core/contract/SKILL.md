# Contract: задача → контракт → инструменты

Пользователь не обязан помнить все скиллы. Этот скилл берёт формулировку задачи, находит подходящую карточку контракта и предлагает короткий план: критерии готовности, доказательства, проверяющего и инструменты. Работа начинается только после согласия.

## Порядок

1. **Подбор.** Запусти роутер на тексте задачи:

   ```bash
   python <skill-dir>/contract.py draft "<задача одной строкой>"
   ```

   `<skill-dir>` это `~/.claude/skills/contract` на установленной машине или `skills/core/contract` в репозитории. Если карточки нет, команда выдаёт общий контракт (Task Passport из `rules/meta-loop.md`): заполни его сам.
2. **Показ черновика.** Передай пользователю контракт целиком: задание, Done when, Evidence, ловушки, список инструментов. Назови уверенность подбора и слова, по которым он сработал. Если уверенность `medium`, спроси, та ли это карточка.
3. **Пороги после базовой линии.** Если у карточки `baseline_first: true`, числовые цели, которых нет в «Done when» («быстрее на X %», «покрытие Y»), не называй, пока не измерена текущая величина. Числа, уже записанные в «Done when», это заявленные цели контракта: сверь их с базовой линией и при необходимости пересмотри до результата. Цифра фиксируется до получения результата.
4. **Утверждение.** Жди явного «да» или правок. Красные и чёрные действия (миграция базы, push, отправка, удаление) контракт не разрешает: на них нужен отдельный «го».
5. **Исполнение.** Запускай инструменты по порядку из контракта. Проверяющий (`verifier`) не тот, кто делал работу: передай ему артефакт без истории рассуждений.
6. **Итог.** Верни статус по словарю карточки (`SUPPORTED / REJECTED / INCONCLUSIVE` и т. п.), а не «готово». Для каждого пункта Done when скажи: выполнен, не выполнен или не проверен, и чем это подтверждено. Не найденное и опровергнутое разные статусы.

## Предложение новых инструментов

Строка «Ещё не пробовали: X» в подсказке означает, что X подходит по смыслу и пользователем ещё не использовался. Попробуй его один раз внутри контракта и отметь в итоге, помог ли он. Больше одного нового инструмента за задачу не берём.

## Что известно о точности подсказки

Измерено 2026-10-14 экспериментом `experiments/20261014-contract-router-precision` (подробности и ограничения там). Истинные запросы размечали независимые слепые разметчики, а не автор правил; 10 147 запросов, 87 сессий, корпус растёт, поэтому повторный запуск даст другие числа. Строгое совпадение карточки:

| | подсказок | верных | точность | охват истинных запросов (оценка, интервал) |
|---|---|---|---|---|
| первая версия (10 карточек, восстановлена) | 660 | 4 | 0,6 % | около 4 % (2–14 %; оценка при знаменателе ~110, до полной разметки) |
| `v1` | 25 | 2 | 8 % (интервал 2–25 %) | 2 из 67 = 3,0 % (после полной разметки) |
| `v1.1` (текущая; правила изменены после эксперимента) | 15 | 2 | 13 % (4–38 %) на тех же данных, это не независимая проверка | отдельно не оценён |

Всего в корпусе 67 истинных запросов после полной разметки (0,66 %, см. `experiments/20261014-contract-router-architectures/decision.md`): три найденных вне кандидатов получены на выборке в 400 и все короткие; ранние оценки около 110 были завышены.

- Подсказка срабатывает редко (0,15 % запросов) и в большинстве случаев мимо. Прежняя оценка «каждая четвёртая по делу» была моим чтением выборки и оказалась завышенной.
- Охват мал не только из-за строгих правил: самое мягкое правило по словам (два слова, без фильтров) находит около четверти истинных запросов при знаменателе ~110, до полной разметки (интервал 13–100 %) ценой точности 1,6 %. Живые короткие просьбы почти не содержат слов карточки.
- Цель «ложных вдвое меньше без потери охвата»: по заранее заявленной первой версии достижима только ценой точности около 3 % (лучшая конфигурация даёт 308 ложных из 317 подсказок); при сравнении правил на одинаковых 41 карточках недостижима: при полном охвате остаётся 70 % ложных. Это вывод про этот корпус и эти 576 вариантов правил, не теорема.
- Критерий «охват не хуже чем на 1 п.п.» на реальных данных не проверяется: нужно порядка 4 000–11 000 истинных запросов, у нас 67.
- Числа `v1.1` не независимы: правило сформировано после чтения классов ошибок этого же корпуса. Настоящая проверка (первые 40 подсказок после 2026-10-14, которые владелец отмечает как полезные или нет) отменена: после решения REMOVE хук не выдаёт подсказок. Правила v1.1 остаются непроверенными на независимых данных.

Вывод: по этим измерениям подсказка в хуке не окупается. Её убрали из ветки (проверка практической пользы, `experiments/20261014-contract-practical-value`, решение REMOVE). Сам навык остаётся: его вызывают вручную через `/contract` или `contract.py draft`, когда задача большая. Патч с убранной подсказкой лежит в `experiments/20261014-contract-practical-value/hook_contract_line.patch`.

## Что скилл не делает

- Не меняет карточки сам. Предложения по правке карточек появляются из отчёта об эффективности и принимаются человеком.
- Не заменяет `/dispatcher` (методология проекта) и `/sci-evidence` (проверка одной гипотезы). Он только выбирает, что из них взять и как понять, что работа закончена.
- Не считает собственный отчёт доказательством: «Done when» подтверждается выводом инструмента, а не пересказом.

## Команды

```bash
python contract.py cards                 # список карточек и известных пробелов
python contract.py route "<задача>"      # одна строка подсказки (хук её больше не выводит)
python contract.py draft "<задача>"      # полный черновик контракта
python contract.py doctor                # маршруты карточек, которых нет в индексе
python contract.py build-index           # пересобрать index.json (после правки карточек или скиллов)
```

Индекс `index.json` генерируется. После добавления скилла или правки карточки пересобери его, иначе подсказки будут отставать (`build-index --check` ловит это в CI).
