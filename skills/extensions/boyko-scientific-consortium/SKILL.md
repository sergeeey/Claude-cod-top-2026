# Boyko Scientific Consortium

## Происхождение и зачем этот скилл существует

Это НЕ новый метод — это компоновка. При проверке (2026-08-04, эта же сессия) выяснилось,
что 70-80% функциональности уже покрыто `sci-evidence` + `hypothesis-arbiter` +
`hypothesis-lab` + `multi-lens` + `~/.claude/rules/estimand-ops.md`. Настоящий пробел —
только: (1) **адаптивный**, а не фиксированный подбор ролей, (2) явная **причинная карта**
как отдельный артефакт для любого класса вопроса (не только causal), (3) четыре
именованных режима, которых нет нигде: Аномалия, Инверсия, Предсказания-до-данных,
Контрфактуальный мир. Этот скилл закрывает именно эти три пробела и **делегирует всё
остальное**, а не переизобретает. См. `docs/skill-disambiguation.md` — семья «консорциум».

## Философия

> Наука прогрессирует через систематическое исключение ложного, а не накопление
> подтверждений. Скрытые причинные связи опаснее явных ошибок — они не спорят с тобой,
> они просто отсутствуют в модели, пока их не начнёшь искать целенаправленно.

## Шаг 0 — EstimandOps L0 Gate (ОБЯЗАТЕЛЬНО, делегируется)

Не реализуется здесь заново. Прогони классификацию по `~/.claude/rules/estimand-ops.md`:
Descriptive / Predictive / Causal — **до** любого дальнейшего шага. Для Causal — DAG
из Шага 3 этого скилла удовлетворяет требованию estimand-ops «DAG + 4 условия
идентификации» (Шаг 3 ниже — это и есть тот DAG, отдельно строить не нужно).

Если тезис расплывчат — не переспрашивай, сформулируй наиболее сильную проверяемую
версию сам и продолжай (Шаг 1 ниже формализует это явно).

## Шаг 1 — Реконструкция тезиса

Прежде чем анализировать — разложи явно, в виде таблицы:

| Поле | Значение |
|---|---|
| Точная формулировка (сильнейшая проверяемая версия) | |
| Переменные | входные / выходные / скрытые |
| Предполагаемый механизм | |
| Уровень объяснения | микро / мезо / макро (см. режим «Уровни масштаба») |
| Границы применимости | где заведомо не работает |
| Наблюдение vs интерпретация | что реально измерено, что достроено рассуждением |

## Шаг 2 — Адаптивный подбор ролей консорциума

**Отличие от `/hypothesis-lab`:** там всегда 9 фиксированных специалистов. Здесь роли
подбираются ПОД задачу — минимум 3, без верхнего предела, но не декоративно (роль
включается только если у неё есть *реальный* вопрос к этому конкретному тезису).

Ростер ролей (не обязателен полностью, выбирай релевантные + добавляй свои при нужде):

```
предметный специалист · историк науки · методолог · статистик/байесианец ·
эксперт по причинному выводу · экспериментатор · инженер измерений ·
специалист по моделированию/симуляциям · философ науки ·
эксперт по воспроизводимости · red-team скептик · эксперт по данным/computational methods
```

Для каждой выбранной роли: **какой конкретный вопрос к тезису она задаёт, которого
без неё не возникло бы**. Если роль не добавляет уникального вопроса — не включай её,
это не театр, а инструмент.

Показывай разногласия между ролями только когда они вскрывают реальную научную
развилку (не разыгрывай спор ради формы).

---

## Шаг 3 — Причинная карта

Обязательный артефакт для ЛЮБОГО класса вопроса (не только Causal из Шага 0):

| Элемент | Вопрос |
|---|---|
| Наблюдаемые переменные | что измерено напрямую |
| Скрытые переменные | что не измерено, но логически должно влиять |
| Конфаундеры | общая причина X и Y |
| Медиаторы | через что X влияет на Y |
| Коллайдеры | переменная, которую нельзя обусловливать без искажения |
| Обратная причинность | может ли Y вызывать X |
| Временные лаги | задержка эффекта, которую легко принять за отсутствие эффекта |
| Селекционные эффекты | как отобрана выборка/данные |
| Feedback loops | усиливающие/уравновешивающие петли |
| Нелинейности, пороги | где линейная интуиция ломается |
| Эффекты масштаба/сети | меняется ли механизм при росте N |

**Невидимые линии** — отдельно выпиши: что пропущено, какие предпосылки неявны,
и (важно) — может ли **отсутствие** наблюдаемого эффекта само быть информацией
(а не просто "нет данных").

## Шаг 4 vs Шаг 5 — выбери ОДИН, не оба (исправлено v1.1, 2026-08-09)

**Известное ограничение первого дожинающего прогона:** таблица «Глубина разбора» ниже
раньше читалась как «на Глубоком разборе — Шаг 4 И Шаг 5 всегда вместе». В реальном
прогоне (см. `confidence` выше) это оказалось неверно и было тихо пропущено без явного
критерия выбора. Правило теперь явное:

| Форма тезиса | Делегируй | Не вызывай |
|---|---|---|
| ≥2 конкурирующих механизма объясняют один и тот же результат | Шаг 4 (`/hypothesis-arbiter`) | Шаг 5 — kill-тесты арбитра уже играют роль mini-FALSIFY |
| Один механизм, нужна доказательная база или его нужно сломать | Шаг 5 (`/sci-evidence`) | Шаг 4 — нечего арбитрировать |
| Оба условия одновременно (редко — ≥2 механизма, и каждый ещё нужно доказывать по отдельности) | Оба, последовательно: Шаг 4 сначала (сузить до выживших), Шаг 5 — только для финального выжившего | — |

### Шаг 4 — Конкуренция гипотез (делегируется)

Если возможных механизмов ≥2 — **не переизобретай**, вызови `/hypothesis-arbiter`
(SPAWN→KILL-DESIGN→IN-SILICO→RED-TEAM→ARBITRATE, включая «Решающий эксперимент» —
этот режим уже там, полностью). Передай ему причинную карту из Шага 3 как контекст.

Если механизм один и конкурентов нет по существу — не вызывай, это ложная генерация
ради формы (`/hyparb`'s own routing table называет это явно: "только один механически
возможный путь" → не его случай).

### Шаг 5 — Фальсификация / доказательство (делегируется)

Вызови `/sci-evidence` (FALSIFY «5 миров» → BUILD «5 путей», Consilience Score).
Не дублируй его протокол здесь — этот скилл добавляет причинную карту и роли
консорциума ДО него и Специальные режимы ниже ПОСЛЕ, сам FALSIFY/BUILD не переписывает.

---

## Шаг 6 — Anti-confirmation чек-лист (то, чего нет полностью нигде в каталоге)

По умолчанию режим — **против** тезиса пользователя: ищи условия, при которых он
должен считаться ослабленным, а не подтверждения. Прогони явно, отмечая наличие/
отсутствие для каждого:

```
cherry-picking · p-hacking · HARKing · survivorship bias · publication bias ·
measurement error · regression to the mean · selection bias · data leakage ·
overfitting · collider bias · Simpson's paradox · Goodhart's law ·
множественные сравнения · нестационарность · внешняя валидность
```

Для каждого найденного риска: конкретный механизм, как именно ОН исказил бы вывод
в ЭТОМ случае (не общий список угроз — точечная привязка к тезису).

## Специальные режимы

Первые два — уже есть в каталоге, вызывай их оттуда, не переписывай:
- **Решающий эксперимент** → `/hypothesis-arbiter` Этап 5 (если гипотез ≥2)
- **FALSIFY «5 миров»** → `/sci-evidence falsify` (если гипотеза одна)

Четыре ниже — реализованы **только здесь**, это ядро добавленной ценности скилла.
**Правило выбора (добавлено v1.1, 2026-08-09):** это то, ради чего скилл вообще
существует — не пропускай их молча. На Глубоком разборе — **минимум 2 из 4**, не
только тот, что первым пришёл в голову (первый дожинающий прогон использовал
только Аномалию, пропустив остальные 3 без объяснения). Критерий, какие два:

| Режим | Бери, когда |
|---|---|
| Аномалия | Почти всегда дёшево и стоит того — что модель объясняет хуже всего |
| Инверсия | Тезис — чёткое бинарное утверждение (верно/неверно), не диапазон |
| Предсказания до данных | Есть ЛЮБАЯ возможность реально проверить что-то ДО того, как увидишь результат (эмпирический тест, замер, поиск источника) |
| Контрфактуальный мир | В причинной карте Шага 3 есть конкретный элемент (confounder/mediator), альтернативное значение которого меняет вывод |
| Уровни масштаба | Явление правдоподобно ведёт себя по-разному на разных N/масштабах (сетевые эффекты, эффекты выборки) |

Если тезис не даёт зацепки ни для одного критерия кроме Аномалии — это сигнал, что
задача, возможно, проще, чем кажется, и `/sci-evidence`/`/skeptic` дешевле (см.
Anti-patterns ниже).

### Аномалия
Какие факты текущая модель объясняет ХУЖЕ ВСЕГО? Не «что подтверждает», а «что
торчит и не влезает». Список аномалий важнее списка подтверждений.

### Инверсия
Что ДОЛЖНО быть верно, если исходная гипотеза НЕВЕРНА? Сформулируй позитивные
предсказания альтернативного мира — не просто «гипотеза ложна», а конкретные
наблюдаемые следствия её ложности.

### Предсказания до данных
Прежде чем смотреть результат — запиши, что гипотеза предсказывает. Если пишешь
предсказание ПОСЛЕ того как увидел результат — это не предсказание, а рационализация
задним числом (тот же принцип, что outcome map в `/hyparb`, но применяется здесь
на уровне всего тезиса, а не отдельного kill-теста).

### Контрфактуальный мир
Сравни: что наблюдалось бы, если бы работал ДРУГОЙ механизм (не конкурирующая
гипотеза целиком, а именно альтернативный causal-путь из карты Шага 3)? Чем это
отличается от Шага 4 (конкуренция гипотез)? Там — целые гипотезы. Здесь — один
элемент причинной карты меняется, остальное фиксировано (mini counterfactual, не
полная альтернативная теория).

### Уровни масштаба
Сохраняется ли объяснение на микро-, мезо- и макроуровне? Явно проверь все три,
даже если тезис сформулирован только на одном — расхождение между уровнями само
по себе диагностическая находка.

## Исторический контекст

Интеллектуальные предшественники, смены парадигм, забытые тупики, спорные
интерпретации. Не называй идею новой без проверки — используй WebSearch для
current literature; предпочитай первичные статьи и мета-анализы, различай препринт
и рецензируемую публикацию, отмечай размер выборки/качество дизайна/конфликты
интересов. Не выдумывай ссылки — `SOURCE_NOT_FOUND`, если не нашёл.

---

## Эпистемическая маркировка

Переиспользует существующую систему CLAUDE.md Evidence Policy, а не вводит
параллельную: `[VERIFIED]` / `[DOCS]` / `[CODE]` / `[INFERRED]` (указать цепочку) /
`[WEAK]` / `[CONFLICTING]` (обе стороны) / `[UNKNOWN]`. Причина не заводить второй
набор меток («установлено/сильное свидетельство/спекуляция/...») — два конкурирующих
словаря evidence-маркировки в одном репозитории хуже одного последовательного.

Для числовых выводов — допущения, неопределённость, чувствительность к параметрам,
базовые частоты явно. Отсутствие данных ≠ отсутствие эффекта — пиши это прямо, когда
применимо.

## Глубина разбора

Не изобретает четвёртую шкалу строгости — маппится на существующую Falsification
Ladder:

| Запрос пользователя | = FL tier | Что входит |
|---|---|---|
| **Быстрый разбор** | Micro | Шаг 1 (тезис) + Шаг 6 (anti-confirmation, коротко) + главные уязвимости |
| **Глубокий разбор** | Standard | + Шаг 2 (роли) + Шаг 3 (причинная карта) + Шаг 4 ИЛИ Шаг 5 (не оба — см. таблицу выбора в разделе «Шаг 4 vs Шаг 5») + **минимум 2 из 4** спецрежимов (см. таблицу критериев в «Специальные режимы») |
| **Максимальный разбор** | Full | Всё + `/hypothesis-lab` (если нужна фиксированная 9-ролевая перепроверка поверх адаптивных ролей) + историч. контекст + **все 4** спецрежима + Шаг 4 И Шаг 5 если оба применимы + репликация/повторное подтверждение |

Если пользователь не указал — выбирай по сложности тезиса, не перегружай простой
вопрос Максимальным разбором.

## Disambiguation — семья «консорциум/гипотезы» (обновлено в docs/skill-disambiguation.md)

| Скилл | Механизм | Когда брать вместо этого |
|---|---|---|
| `sci-evidence` | FALSIFY/BUILD одной гипотезы, без причинной карты и ролей | Гипотеза одна, причинная структура не нужна, нужна скорость |
| `hypothesis-arbiter` | Конкуренция ≥2 гипотез, kill-тесты | Уже есть чёткий список гипотез-конкурентов, причинная карта не нужна |
| `hypothesis-lab` | ФИКСИРОВАННЫЕ 9 специалистов, Lab Consensus Score | Нужна конкретно эта панель/скоринг, не адаптивный подбор |
| `multi-lens` | 20 универсальных линз для ЛЮБОГО объекта (не только гипотезы) | Объект — не гипотеза (архитектура, код, стратегия) |
| `skeptic` | Точечная одноразовая атака одной идеи | Не нужна причинная карта/роли/спецрежимы, нужна just атака |

**Правило:** если тезис — гипотеза, нужна причинная карта, и/или нужны Аномалия/
Инверсия/Предсказания-до-данных/Контрфактуальный мир — этот скилл. Если нет ни
одного из этих трёх — один из скиллов выше дешевле и быстрее.

## Anti-patterns

| Сигнал | Диагноз | Действие |
|---|---|---|
| Все роли Шага 2 включены "на всякий случай" | Театр, не инструмент | Оставь только роли с реальным уникальным вопросом |
