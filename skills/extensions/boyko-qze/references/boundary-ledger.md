# Boundary Ledger — журнал гипотез о границах

Читай при формировании вывода в режимах BOUNDARY, DEEP, RESEARCH, CROSS-DOMAIN, и когда
пользователь просит экспорт. В режиме QUICK достаточно одной строки.

Журнал живёт **в пределах беседы**. Между беседами память не обещай: хранилище не подключено.
Если нужно сохранить, используй существующие каналы: `/capture` (маршрутизация по таблице
памяти) или запись в Obsidian по явной просьбе. Новый файл-хранилище не создавай.

## Поля записи

| Поле | Содержание |
|---|---|
| `case_id` | `QZE-<проект>-<YYYYMMDD>-<n>` |
| `claim_version` | v1, v2… (если был Frozen Claim) |
| `frame` | Исходная рамка одной фразой |
| `mechanism` | M1–M10 и статус (`fact` / `inference` / `hypothesis` / `unknown`) |
| `missing` | Недостающее понятие или измерение |
| `class` | Новый класс вопросов |
| `questions` | 1–3 конкретных вопроса |
| `source` | Откуда взято: сообщение пользователя, файл, URL; `[MEMORY]`, если из памяти модели |
| `alternative` | Альтернативное объяснение (в том числе нулевое или артефактное) |
| `discriminating_test` | Тест, различающий границу и альтернативу |
| `falsifier` | Условие отказа |
| `verification_status` | `PROPOSED` / `READY` / `RUN` / `INCONCLUSIVE` / `BLOCKED` |
| `novelty` | Отдельно: лексическая / концептуальная / новый прогноз; внешняя новизна `unverified` без поиска |
| `scores` | Подтверждённость механизма, масштаб класса, проверяемость, ценность (каждое 0–3), риск спекуляции (0–3). Это эвристика, не показатель |
| `status` | `open` / `tested` / `dropped` / `parked` |

## Дедупликация

Перед добавлением записи сверь её с уже существующими в беседе **по механизму, а не по
названию** (наш P10: одна гипотеза убивалась трижды под разными именами). Если механизм
совпадает, это та же запись: увеличь счётчик, не заводи новую.

## Шаблон Markdown

```markdown
### QZE-<проект>-<дата>-<n> (v1)
- Рамка: …
- Механизм: M? (inference) — посылки: …
- Недостаёт: …
- Класс вопросов: …
- Вопросы: 1) … 2) … 3) …
- Источник: …
- Альтернатива: …
- Различающий тест: … [PROPOSED]
- Условие отказа: …
- Новизна: лексич. … / концепт. … / прогноз … / внешняя: unverified
- Оценки: M=_ S=_ T=_ V=_ риск=_ (эвристика)
- Статус: open
```

## Что журнал не делает

- Не ранжирует записи как авторитет: сумма оценок — рабочая эвристика. Наш P20 показал, что
  LLM-ранжирование следует длине текста (Spearman 0,71 на n=10); поэтому не ставь непроверяемое
  выше проверяемого только за неожиданность.
- Не копит обещаний «запомню». Если пользователь хочет сохранения, это отдельное действие с
  отдельным подтверждением.
