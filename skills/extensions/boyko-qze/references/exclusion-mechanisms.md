# Карта механизмов исключения вопросов

Читай на шаге 4. Для каждой границы назначь ОДИН основной механизм и (если есть) один
конкурирующий. Механизм — это ответ на «почему этот вопрос не возникает», а не описание самого
вопроса. Если не можешь назвать механизм, у тебя пока нет границы, а есть интересный вопрос.

Нумерация M1–M10 соответствует пунктам (а)–(к) исходной спецификации QZE v0.3 по порядку.
Примеры в таблице — иллюстрации того, как выглядит механизм. Они не доказательство того, что
механизм действует в твоём кейсе (Artifact Provenance Gate 2: иллюстрация, процитированная три
раза, становится «результатом»).

## Статус каждого механизма

Каждому присвой одну метку и укажи происхождение:

- `fact` — прямо сказано в предоставленных материалах или проверено по источнику;
- `inference` — вывод; перечисли посылки;
- `hypothesis` — одно из конкурирующих объяснений;
- `unknown` — не установлено.

Для каждого `inference` и `hypothesis` запиши **контргипотезу**: при каком положении дел исходная
постановка оптимальна и границы нет. Если контргипотезу сформулировать нельзя, значит, ты
защищаешь вывод, а не проверяешь его.

## Различай три вещи, которые легко склеить

1. **Вопрос не задан** (никто не догадался) — это не граница, это пробел внимания. Лечится
   одним хорошим вопросом.
2. **Вопрос не может быть задан в этой рамке** (грамматика не допускает) — это граница. Лечится
   сменой рамки.
3. **Вопрос задан, но не может быть проверен** — это механизм M9, а не граница вопросов.

Неизвестность не равна несуществованию. Непопулярность вопроса не равна запрету.
Оригинальность формулировки не равна научной новизне.

## Один механизм или два

В режимах BOUNDARY и DEEP, если данных хватает, ищи минимум два конкурирующих механизма для
главной границы. Если данных не хватает, напиши «второй механизм не построен: нет X», а не
изобретай его ради симметрии (Competing Hypothesis Engine: `unknown`, а не искусственное
противостояние).
