# Журнал калибровок

Читай, чтобы понять, что уже проверено на реальных системах и чего нет. Все числа получены
командами в сессии 2026-11-04; приватные тексты в журнал не входят, только счётчики.
Статусы: `[VERIFIED-REAL]` — реальные данные нашего проекта; `[VERIFIED-SYNTHETIC]` — подсаженные
дефекты или игрушечные таблицы.

## Прогон 1. Хук `routing-floor` на сообщениях других сессий `[VERIFIED-REAL]`

- Корпус: 4772 записи из 32 транскриптов проекта; происхождение записи (человек, другая
  сессия, уведомление системы) указывает сам харнесс, поле `origin.kind`, а не мы.
- Метрика: доля сообщений не от человека, на которых хук срабатывает (должно быть 0).
- Было: 89 из 109 сообщений других сессий; 0 из 689 уведомлений.
- Три кандидата (блок `<agent-message>` не вырезается; преамбула и хвостовой комментарий;
  другая обёртка). Таблица 2^3: только первый даёт эффект (89 → 0), остальные ноль.
- Скрипт: `SINGLE_DOMINANT`, взаимодействий нет, `budget_ratio` 1.0. Защита: на 2565
  человеческих промптах набор срабатываний не изменился.
- Оговорка: кандидатов называл автор скилла; оказался один очевидный.

## Прогон 2. Калибровка подсаженными дефектами `[VERIFIED-SYNTHETIC]`

- Подсадчик (отдельный агент) спрятал два дефекта в копии того же хука: в вырезании служебных
  блоков (вклад 133 из 140) и в регулярке уровня DESTRUCTIVE (вклад 13), взаимодействие 6.
  Ключ запечатан, искатели его не видели. Нулевая копия без дефектов, имена нейтральные,
  порядок случайный.
- Искатель 1 нашёл оба места и точные правки, вклады 130 и 10, взаимодействие 6, отклонение
  140 → 0. Искатель 2 на нулевой копии вернул `NO_CONSTRAINT_DETECTED`, ничего не выдумав.
- Выявленные изъяны скилла: смешение единиц шума и значений (ошибка инструкции, дала ложное
  «дополняющие»); вердикт `SINGLE_DOMINANT` не показывал второй реальный дефект (теперь
  `also_real`). Нулевой контроль был лёгким (отклонение 0 видно сразу).
- Оговорка: скорер показывал лишние и пропущенные срабатывания по уровням, это сильно
  сужало поиск. 2 из 2 найденных дают нижнюю границу доли находимых дефектов около 34% (Уилсон).

## Прогон 3. Парсер вердиктов каталога экспериментов `[VERIFIED-REAL]`

- Проблема: 188 из 628 записей каталога (30%) с вердиктом `UNKNOWN`, при этом у 188 есть
  файл решения; текущий парсер не распознал вердикт ни в одном.
- Эталон: два независимых разметчика-агента прочитали по 60 файлов; согласились на 54
  (51 с вердиктом, 3 «вердикта нет»); исключено 6 (неоднозначно или расхождение).
  Правило сравнения слов записано до просмотра.
- Разделение 27 / 27. Искатель видел только первую половину и защиту из 435 уже верных файлов.
- Скрипт: `MULTIPLE_CONSTRAINTS`, `budget_ratio` 1.52, перекрытие двух ограничителей. Главный:
  потолок 40 символов на слово вердикта. Часть правок оказалась нечистой (G > 0 при встраивании
  в основную цепочку); искатель честно пометил это и переделал правки как запасной шаг (с
  раскрытием).
- Результат на скрытой половине (ошибок из 27): исходный парсер 25; запасной шаг 7; строгая
  версия без нечистых правок 23. На открытой половине 26 → 5 и 24. Прогноз искателя «переживёт
  55–70%» оказался заниженным: переживает 18 из 21.
- Остаётся: 1–3 неверных слова на половину (например `OB1`), вердикты внутри прозы, статус
  вместо вердикта.
- Оговорки: выборка взята только из строк с `UNKNOWN` (точность на остальных 440 строках не
  измерена); эталон из двух агентов, не людей; защита G=0 отчасти верна по построению (запасной
  шаг не трогает уже распознанное); n = 27 + 27.
