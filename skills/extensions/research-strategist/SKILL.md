# Research Strategist — LBD + Hypothesis Validation

Сквозной маршрут «неясный research-вопрос → проверяемая исследовательская карта». **Это оркестратор:** большинство этапов делегируются готовым скиллам — не дублируй их. Своё ядро у скилла одно — **проверка параметров на подгонку** (Шаг 5), которой нет в других скиллах.

```
Вопрос → Формулировка → Декомпозиция → Конкуренты → Забытые идеи
       → ПОДГОНКА(своё) → Red-team → Kill-test → Вердикт (+ Opportunity)
```

**Главный принцип (из integrity.md):** не доказывай гипотезу. Выясни, при каких условиях она выживает честную проверку, а при каких ложна.

Скилл = маршрут + делегирование.

## Шаг 0 — EstimandOps L0 Gate (обязательно для research)

Классифицируй вопрос: descriptive / predictive / causal (`rules/estimand-ops.md`). Без этого декомпозиция параметров бессмысленна — неясно что измеряем.

## Шаг 1 — Строгая формулировка

Переформулируй в проверяемый вид: гипотеза · ключевой спор · критерии истинности. Прогон через Zero-Signal Gate: если нет (entity ∧ falsifiable predicate ∧ measurable outcome) → `REFUSE`, дальше не идём.

## Шаг 2 — Декомпозиция → делегируй `claim-decomposer`

Разложи на claims / assumptions / parameters / unknowns. Не переписывай формат — вызови `/claim-decomposer`. Каждый атом несёт EVIDENCE_TYPE.

## Шаг 3 — Конкурирующие объяснения → делегируй `hypothesis-arbiter`

Минимум 3 объяснения (заявленное + альтернатива + «артефакт/подгонка») по Chamberlin+Platt. Не изобретай — вызови `/hypothesis-arbiter`. Выход: kill-test на каждое + confidence.

## Шаг 4 — Забытые/недопроверенные идеи → делегируй `hypothesis-revival` + `lit-search`

Старые гипотезы, объясняющие тот же эффект; семантические аналоги из других областей. **Pre-work check:** если у проекта есть архив отклонённых/отложенных гипотез — просмотри его ПЕРЕД поиском.

## Шаг 5 — Проверка параметров на подгонку (ЯДРО скилла — своё)

**Это то, чего нет в других скиллах.** Для каждого численного параметра/константы/метрики:

| Параметр | Заявл. значение | Ожидаемое (независимо) | Источник значения | Критичность для вывода | Риск подгонки | Статус |
|----------|----------------:|----------------------:|-------------------|------------------------|---------------|--------|

Проверь по каждому: размерность · порядок величины · нормировка · физ.смысл · чувствительность вывода к параметру · допустимый диапазон из первых принципов · **есть ли независимая оценка вне текущей подгонки** · можно ли вывести из других известных величин.

**Решающий тест подгонки:** параметр обоснован ТОЛЬКО если выведен из независимой модели / независимого измерения / физического ограничения — НЕ из фита к тем же данным, которые он объясняет. Иначе `is_parameter_likely_empirical_fit: high`.

**Degeneracy-чек:** если несколько разных параметров дают тот же результат → вывод не идентифицируем, отметь явно.

Самопроверка: прежде чем писать «непонятно откуда параметр» — попробуй вывести его сам (5-мин расчёт) и прогони контрольный случай, чтобы отличить универсальную закономерность от подгонки под один случай.

## Шаг 6 — Red-team → делегируй `skeptic`

Слабые места: observational bias · selection effect · degeneracy · малая выборка · overfitting · circular reasoning · post-hoc fitting · конфликт с независимыми наблюдениями · более простое объяснение. Context asymmetry: `skeptic` получает ТОЛЬКО claim + параметры, без истории рассуждений (из falsification-ladder).

## Шаг 7 — Kill-test

Минимальный решающий тест, у которого гипотеза имеет **реальный шанс проиграть**: цель · нужные данные · метод · результат-если-верна · результат-если-ложна · условия неинформативности · стоимость · почему результат решающий. Если тест не может опровергнуть — это не kill-test, переделай.

## Шаг 8 — Вердикт + Opportunity Map

Вердикт: `proceed / proceed_with_caution / needs_more_data / weak / reject / redesign` + сильнейшее доказательство + слабейшее место + `is_parameter_physically_justified` + `what_would_change_my_mind` + confidence с явным обоснованием (не число).

**Side-insight:** после вердикта — отметь неожиданный, но проверяемый побочный инсайт (с триггером и датой повторной проверки), если есть.

## Маркеры достоверности (расширенный набор)

Поверх integrity.md этот скилл использует градацию: `[VERIFIED-REAL]` · `[PARTIALLY-VERIFIED]` · `[INFERRED-HIGH]` · `[INFERRED-MEDIUM]` · `[SPECULATIVE]` · `[UNVERIFIED]` · `[HALLUCINATION-RISK]` · `[UNKNOWN]`. Золотое правило: не выдумывай DOI/авторов/датасеты/числа — нет источника → `[UNVERIFIED]` явно.

## Режимы

- **Режим: быстро** — 5 блоков: вывод · что подтверждено (источники) · что сомнительно · конкуренты · следующий тест.
- **Режим: глубоко** — все шаги (0–8) + полный формат из этого файла.

## Overhead-гейт (когда НЕ запускать)

Полный маршрут дорог. Для точечной задачи бери один скилл:
- сломать одну гипотезу → `/sci-evidence falsify` (5 миров);
- построить доказательную базу → `/consilience` (5 путей);
- одна идея на разлом → `/skeptic`;
- сгенерировать гипотезы → `/sci-hypothesis`.
Полный research-strategist — только для сложной гипотезы, где цена ошибки высока (claim к публикации, ключевое research-решение).

## Чем НЕ является

Не замена `hypothesis-arbiter`/`skeptic`/`claim-decomposer` — он их **вызывает**. Не генератор гипотез. Его уникальный вклад — **проверка параметров на подгонку** + сшивка LBD-этапов в один воспроизводимый маршрут с вердиктом.
