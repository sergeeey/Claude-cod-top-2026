# Coverage and challenge

Read this file when stakes are high, when many external actors exist, or when a missing scenario would be costly.

A set of plausible branches does not mean the map is complete. After the first graph is built, challenge it. The purpose is not to add branches mechanically. The purpose is to test whether the important mechanism classes are covered.

## 1. The challenge checklist

Ask each question and record the answer, even if the answer is "not relevant here":

1. What important mechanism class is missing?
2. What happens without any new intervention?
3. Could another actor change the path?
4. Could an external shock invalidate the map?
5. Could the rules or the reference state change?
6. Is there a realistic but unpleasant branch we omitted?
7. Are we assuming a stable regime?
8. Could feedback reverse the current direction?
9. Is there a delayed effect?
10. Which important uncertainty remains outside the graph?

## 2. Baseline / no-new-intervention path

Question: what is likely to continue if no important new action or shock occurs?

Purpose: this stops every scenario from implicitly assuming a new intervention. It is a comparison path. It is not necessarily the most likely future.

Representation:

```
BASELINE / NO-NEW-INTERVENTION PATH
S0 → S5
```

When the baseline is not useful (for example, when a fixed event already dominates everything), state why and skip it.

## 3. External actor

Who else can act, and does their action change the path?

Check: parallel actors, competitors, regulators, suppliers, users, researchers, rival groups, platforms. For each: what do they gain or lose from the change, and what could they do in response?

## 4. External shock

Which unexpected disturbance would invalidate the map? Examples: a failure of a key dependency, a sudden price change, a security event, an accident, a natural disaster, a sudden loss of a person or a resource.

Ask: does the map still hold under the shock, or does it need a new starting state?

## 5. Reference shift

Could the apparent change come from the reference state rather than the target itself?

Keep two records: OBJECT CHANGE and REFERENCE CHANGE. Example: a branch looks stale. Either its files changed, or the main line moved on while the branch stayed fixed. These imply different actions.

## 6. Rule change

Could a law, standard, incentive, permission or policy change the rules of the game? A rule change often produces a structural effect that outlasts the event that caused it.

## 7. Regime shift

Could the system move from one regime to another, where the old relationships no longer hold? Test the map's assumptions: which of them would fail in a different regime?

## 8. Delayed effect

Is there a known delayed mechanism that could later reverse or dominate the near-term difference? Look especially for lock-in, accumulated debt, reputation effects, learning effects and cumulative commitments.

## 9. Feedback

Could effects loop back to their own drivers? Check reinforcing loops (growth that feeds itself) and balancing loops (growth that brings its own limit). A feedback claim needs a plausible mechanism.

## 10. Adversarial response

Would a rival or opponent deliberately respond to the trajectory? An adversary can change the path by reacting to the first move, by copying it, or by blocking it. Treat the adversary's best response as a branch when it is realistic.

## 11. Unknown unknown

Some important mechanisms will not appear in any list. Write a residual-uncertainty entry for them. Do not pretend the list is complete.

## 12. Branch control

Prefer 2–4 materially different trajectories.

Add a branch only if:
- a distinct mechanism exists;
- the branch changes the interpretation;
- the branch changes future decisions;
- the branch changes risk materially.

Mechanism diversity is worth more than branch count. Five branches that share one mechanism are one branch.

Merge two branches when they remain equivalent under the State Equivalence Gate and the Decision Relevance Gate.

## 13. Decision relevance, in detail

Keep a difference only if it changes at least one of:
- a future action;
- understanding of a mechanism;
- risk exposure;
- resource position;
- capability;
- a constraint;
- an irreversible commitment;
- the future option set;
- a strategic position;
- a research conclusion;
- monitoring priority.

The question is not "what is the earliest difference?" It is "what is the earliest decision-relevant or knowledge-relevant difference?"

## 14. Counterevidence for each trajectory

For every major trajectory, answer:
- What evidence argues against this path?
- What mechanism could stop it?
- Which assumption is fragile?
- What alternative explanation exists?
- What observation would make us downgrade this trajectory?

A trajectory without counterevidence is incomplete.

## 15. Residual uncertainty wording

Say explicitly when it matters:

"These branches are the main modeled trajectories. They are not an exhaustive set of possible futures. Residual uncertainty includes unknown unknowns, unmodeled actor behaviour, structural breaks, measurement error, unobserved constraints, future technologies and policy surprises."

Keep only the items that apply to the case.

## 16. Stopping after the challenge

Stop challenging when a new question no longer changes the interpretation, the decision, the risk or the monitoring plan. Continuing after that produces noise, not coverage.
