# Проверка вывода «Умные напоминания снижают отток на 84 %»

## Вывод

Так утверждать нельзя, и закладывать 84 % в финплан тоже нельзя. Цифры отчёта воспроизводятся: `python analysis.py` даёт 8,0 % против 51,5 %, снижение 84 % и корреляцию −0,49. Но часть «эффекта» создаёт сама методика. Данные не рандомизированы, поэтому настоящий эффект по ним установить нельзя. После выравнивания окон и поправки на состав групп снижение оттока падает с 84 % до 29–48 % на выборке аналитиков (`cs_call = 1`). Если не отбирать клиентов по `cs_call`, оно падает до 29–40 %. В сегменте без звонка (`cs_call = 0`) оно составляет всего 3–10 %. Остаточное смещение вероятно и в этих оценках, потому что клиенты сами включают функцию.

## Что найдено

**1. Разные окна наблюдения (ошибка в коде).**
- В `analysis.py`, строка 45, для группы с функцией берётся `churned_180d`. В строке 46 для группы сравнения берётся `churned_365d`. Полугодовой отток сравнивается с годовым.
- Отчёт (п. 4 методики, строки 34–35) описывает это иначе: «с момента включения» и «за отчётный год». Дат включения в данных нет, так что проверить это описание нельзя.

Пересчёт на выборке аналитиков (не trial, `cs_call = 1`):

| Окно | С функцией | Без функции | Снижение |
|---|---|---|---|
| 180 дн. против 365 дн. (как в отчёте) | 8,0 % | 51,5 % | 84 % |
| 180 против 180 | 8,0 % (356 из 4 432) | 24,3 % (837 из 3 450) | 67 % |
| 365 против 365 | 14,7 % (653) | 51,5 % (1 777) | 71 % |

Одно только выравнивание окон снимает 13–17 п.п. из 84 %.

**2. Фильтр `cs_call = 1` отбирает группы по-разному.**
- Отчёт (строки 29–31) берёт клиентов со звонком менеджера как «более полные данные». Доля звонков по группам сильно различается: у «on» 4 432 из 5 505 (80,5 %), у «never» 3 148 из 15 708 (20,0 %).
- Отток за 365 дн. у «never» зависит от звонка: 50,6 % со звонком и 26,8 % без. У «on» не зависит: 14,7 % и 13,8 %. Фильтр оставляет в контроле клиентов с повышенным риском, а в группе функции такого сдвига нет.
- Почему менеджер звонил, в данных не видно. [UNKNOWN]

Поправка на срок жизни и активность (Mantel-Haenszel; «on» против «never + disabled»):

| Сегмент | Снижение оттока, 365 дн. | Снижение оттока, 180 дн. |
|---|---|---|
| `cs_call = 1` | 48 % | 37 % |
| `cs_call = 0` | 10 % | 3 % |
| все не-trial | 40 % | 29 % |

Разброс между 48 % и 10 % может означать реальную связку «функция + звонок». Может означать и отбор. Эти данные различить не позволяют.

**3. Группы различаются по составу.**
- Доля клиентов с высокой активностью до запуска: 80,4 % у «on» и 30,3 % в группе сравнения. Доля долгих клиентов (`long`): 51 % и 15 %.
- Сама активность сильно предсказывает отток. В `long` у «never» отток за 365 дн. равен 13,5 % при высокой активности и 38,0 % при низкой.
- Внутри ячеек срок × активность разрыв меньше. Для `long/high` это 6,6 % против 13,5 %, для `mid/low` 28,7 % против 50,3 %.
- Поправка учитывает только два грубых признака: срок и активность «low/high» за один месяц. Клиенты включали функцию сами, и вовлечённые включают её чаще, поэтому остаточное смещение вероятно.
- E-value для RR 0,57 равен 2,9. Скрытый фактор с таким усилением и по включению, и по оттоку объяснил бы весь эффект. Наблюдаемая активность сама даёт отношение оттока около 2, так что это правдоподобно.

**4. Группа «disabled» в контроле и обратная причинность.**
- В группу сравнения (`analysis.py`, строка 43: `!= "on"`) попали 302 клиента «disabled» с оттоком 60,9 % за 365 дн.
- Лог `feature_disable_log.csv` (60 событий) показывает порядок: падение активности, затем отключение, затем уход. Отключение идёт позже падения в 60 из 60 случаев, лаг 7–44 дня, медиана 23,5.
- Из 39 клиентов с датой ухода все 39 ушли после отключения, лаг 8–103 дня, медиана 63. У 21 из 60 даты ухода нет.
- Статус «функция включена на конец периода» частично зависит от того, что клиент не начал «затухать». Это отбор по исходу, в пользу «on».
- Сам лог эффект функции не оценивает: в нём только отключившие, группы сравнения нет, способ выборки 60 строк неизвестен. В расчётах отчёта лог не используется.

**5. Статистика и экстраполяция.**
- Непересекающиеся доверительные интервалы (отчёт, строка 47) говорят лишь о том, что разница не случайна. Смещения из пп. 1–4 они не учитывают.
- Корреляция −0,49 считается на смешанных окнах (`analysis.py`, строки 54–63). При равных окнах phi = −0,23 (180 против 180) и −0,40 (365 против 365).
- «Сократит отток в шесть раз» несовместимо с данными. 6,4 = 51,5 / 8,0 — это отношение внутри выборки. По всей базе годовой отток равен 31,1 % (7 458 из 24 000). Если довести всех не-trial клиентов до 14,7 % (без поправок), он станет 19,3 %, то есть упадёт в 1,6 раза.
- Функцию уже имеют 25,4 % не-trial клиентов. Trial (2 367, 9,9 % базы) её получить не может.

**Сценарии для финплана.** Расчёт по 16 128 не-trial клиентам без функции за 365 дн.:
- RR 0,57 даёт около 2 240 удержанных клиентов.
- RR 0,81 даёт около 990.
- Нулевой эффект даёт 0.

Это показатель разброса, а не прогноз.

## Что предлагаю

3. До теста держать в финплане диапазон от 0 до примерно 40 % снижения оттока среди клиентов без функции. Базовым сценарием взять 0. Это граница того, что допускают данные, а не оценка эффекта.
