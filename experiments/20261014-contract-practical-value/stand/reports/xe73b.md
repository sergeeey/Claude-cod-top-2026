# Проверка вывода «Умные напоминания снижают отток на 84 %»

## Итог

Так утверждать нельзя. Цифры 8,0 % и 51,5 % воспроизводятся командой `python analysis.py`. Но сравнение собрано из несопоставимых частей и не измеряет эффект функции.

После исправления окон и учёта срока жизни и активности связь остаётся слабой: относительное снижение 10–15 %. Это всё ещё ассоциация, а не доказанная причина. Закладывать 84 % или «в шесть раз» в финплан нельзя. Включать функцию всем по умолчанию без эксперимента я не рекомендую.

## Причинная модель (допущения)

Переменные:
- T: функция включена.
- Y: уход клиента.
- A: активность до запуска.
- L: срок жизни клиента.
- C: звонок менеджера (`cs_call`).
- S: попадание в выборку анализа (`cs_call = 1`, не `trial`, статус функции на конец периода).

Чтобы читать 84 % как причинный эффект, нужны допущения, которые здесь не выполняются:
- A влияет и на T, и на Y: активные клиенты чаще включают функцию и реже уходят.
- L влияет и на T, и на Y: давние клиенты тоже чаще включают и реже уходят.
- Обратная причинность: падение активности ведёт к отключению функции, потом к уходу.
- Риск влияет на звонок C, а C влияет на Y. Фильтр `cs_call = 1` отбирает клиентов по следствию риска.
- Статус «on» измерен на конец периода, то есть условен на то, что клиент ещё не ушёл.
- Нужна обменяемость групп (нет неучтённых конфаундеров), позитивность и одинаковые окна измерения. Ни одно условие не выполнено.

## Что найдено

### 1. Разные окна в двух группах (ошибка скрипта)

`analysis.py:45` считает отток «с функцией» по `churned_180d`. `analysis.py:46` считает отток «без функции» по `churned_365d`. Корреляция −0,49 (`analysis.py:54-62`) посчитана на том же смешанном окне.

Те же 7 882 клиента (`xe73b_check.py`, блок A):

| Окно | С функцией | Без функции (never + disabled) | Относительное снижение |
|---|---|---|---|
| Как в отчёте: 180 д против 365 д | 8,0 % | 51,5 % | 84 % |
| Оба 180 д | 8,0 % | 24,3 % | 67 % |
| Оба 365 д | 14,7 % | 51,5 % | 71 % |

### 2. Отбор по `cs_call = 1`

Звонки идут не случайным клиентам:
- Доля клиентов со звонком: у «on» 80,5 %, у «never» 20,0 %.
- Внутри «never» отток за 365 дней: без звонка 26,8 % (n = 12 560), со звонком 50,6 % (n = 3 148). Менеджеры звонят рискованным.
- В выборке `cs_call = 1` группа сравнения состоит из рискованных клиентов, поэтому контраст завышен.

На всей базе без `trial` (все `cs_call`) сырой контраст почти вдвое мягче:

| Окно | on | не on | Относительное снижение |
|---|---|---|---|
| 180 д | 8,0 % (n = 5 505) | 17,0 % (n = 16 128) | 53 % |
| 365 д | 14,6 % | 32,3 % | 55 % |

### 3. Конфаундинг: функцию включают самые «живые» клиенты

Доля высокой активности: у «on» 80,1 %, у «never» 37,7 %. Доля `long`: у «on» 51,5 %, у «never» 18,5 %.

Сравнение on и never внутри ячеек «срок × активность» (все `cs_call`), стандартизовано на состав группы «on»:
- 365 д: on 14,6 %, never 17,1 %. Снижение 15 % (2,5 п.п.).
- 180 д: 8,0 % против 8,9 %. Снижение 10 %.
- Внутри ячеек разница мала. Например, `new/low`: 50,3 % против 49,6 %; `long/high`: 6,5 % против 8,3 %.

Основную часть «эффекта» объясняет то, кто включает функцию, а не сама функция. Остаток 10–15 % может быть остаточным конфаундингом: ковариатов всего два и они грубые.

Чувствительность (E-value для отношения рисков never/on):

| Оценка | RR | E-value |
|---|---|---|
| 365 д, стандартизовано | 1,17 | 1,62 |
| 180 д, стандартизовано | 1,11 | 1,47 |
| `cs_call = 0`, 365 д | 1,09 | 1,39 |

Неучтённый фактор (вовлечённость, тариф, сегмент) с силой связи около 1,4–1,6 и с T, и с Y способен свести оценку к нулю.

### 4. Обратная причинность и группа «disabled»

В `feature_disable_log.csv` 60 событий. У 21 из них `churn_day` пуст, то есть не ушли или данные цензурированы. Анализ идёт по 39 событиям с полными датами:
- В 39 из 39 случаев падение активности раньше отключения, а отключение раньше ухода.
- Медиана «падение → отключение» 25 дней (7–44). Медиана «отключение → уход» 63 дня (8–103).

Функцию выключают клиенты, которые уже уходят. Статус «on» выбирает тех, кто ещё не начал уходить. Группа `disabled` (302 клиента при `cs_call = 1`, отток за 365 дней 60,9 %) лежит в контроле и завышает его отток. Но это тоже отбор по следствию.

Оговорка: лог выборочный (60 событий), его репрезентативность не описана. Он не доказывает, что функция бесполезна.

### 5. Статистика

Интервалы Уилсона посчитаны верно. Но довод «интервалы не пересекаются, значит эффект значим» не помогает. Интервал описывает случайную ошибку, а здесь ошибка систематическая: окна, отбор, конфаундинг.

`trial` исключён обоснованно. Но тогда оценка не переносится на эти клиентов, а «включить всем» их как раз затронет.

## Идентифицируемость и что её нарушит

Претензия: «включение функции снижает отток».
- Согласованность окон нарушена.
- Обменяемость нарушена. Наблюдаемые A и L её не восстанавливают, а остальное (вовлечённость, тариф, влияние менеджера) непроверяемо.
- Позитивность слабая: в `new/low` включили 193 из 4 944 клиентов (3,9 %), а в `long/high` включили большинство. В отдельных ячейках оценка опирается на мало наблюдений «on».
- Нет даты включения функции, поэтому анализ «до/после» невозможен.
- Рандомизации нет. Идентифицируемость на этих данных не достигается, вывод остаётся ассоциативным.

## Конкурирующие объяснения и их проверка

| Объяснение | Проверка | Результат |
|---|---|---|
| Эффекта нет, всё объясняет, кто включает | Стандартизация по сроку и активности | Разница падает с 84 % до 10–15 %. Объясняет основную часть |
| Артефакт окон | Одинаковые окна | 84 % падает до 67–71 % |
| Отбор по звонку менеджера | Звонок против его отсутствия внутри never; стандартизация по `cs_call` | Риск ведёт к звонку (26,8 % против 50,6 %). При `cs_call = 0` снижение 8 % (13,8 % против 15,0 %), при `cs_call = 1` 47 %. Фильтр завышает эффект |
| Обратная причинность | Хронология в логе | 39 из 39: падение активности раньше отключения |
| Небольшой реальный эффект | Остаток после стандартизации | Не отвергнут и не подтверждён |

Отрицательного контроля в данных нет: нет исхода, на который функция не должна влиять. Ближайший аналог — срез `cs_call = 0`, где отбор по звонку слабее. Он даёт около 8 %.

## Что предлагаю

1. Не использовать 84 % и «в шесть раз» в финплане. Если нужна цифра для планирования, консервативно закладывать 0 %. Возможный эффект до 10–15 % относительно — это оценка сверху, не ожидание.
2. Попросить аналитиков пересчитать с одинаковым окном от даты включения, без фильтра `cs_call`, со стандартизацией или матчингом по сроку жизни, активности, тарифу и сегменту. Добавить в данные дату включения.
3. Вместо включения всем запустить рандомизированный пилот: случайные 10–20 % клиентов с функцией по умолчанию, остальные без неё, на 180–365 дней, с оттоком в одном окне. Размер выборки считать на минимальный значимый эффект. Если реальный эффект около 2,5 п.п. при базовом оттоке около 17 %, нужны тысячи клиентов на группу.
4. Если рандомизация невозможна, включать функцию поэтапно, случайными партиями клиентов.
5. Решение по финплану отложить до результатов пилота. Риски включения по умолчанию (раздражение клиентов, отписки) аналитики не рассматривали.
