# Прогноз покупки в сессии

Модель предсказывает, закончится ли сессия пользователя покупкой. Планируемое
использование: раз в неделю переобучаем модель на всей накопленной истории и
по её прогнозам решаем, кому из пользователей показывать персональное
предложение в сессиях следующих недель.

## Данные

`data.py` воспроизводит выгрузку журнала сессий интернет-магазина за 180 дней
(около 300 пользователей, у каждого от 6 до 15 сессий). Одна строка — одна
сессия. Колонки:

| колонка | смысл |
|---|---|
| `user_id` | идентификатор пользователя |
| `day` | номер дня сессии (0..179) |
| `pages` | число просмотренных страниц (иногда не логируется) |
| `price` | нормированная цена просмотренных товаров |
| `discount` | была ли показана скидка |
| `f1..f3` | характеристики устройства и браузера |
| `prev_buys` | сколько покупок пользователь сделал в своих прошлых сессиях |
| `n0..n24` | прочие технические поля журнала |
| `y` | 1, если сессия закончилась покупкой |

Акция со скидками действовала до 120-го дня.

## Модель

`train.py`: признаки плюс средняя доля покупок пользователя (`user_rate`),
стандартизация, ранжирование признаков по корреляции с целевой переменной,
отложенная выборка 25 %, заполнение пропусков медианой, удаление повторов в
обучающей части, k ближайших соседей. Число признаков и `k` подбираются по
сетке, качество меряется ROC AUC.

Запуск (нужен только numpy):

```
python train.py
```
