# phase0_report.md — инвентаризация категорий (фаза 0, шаг 1–2)

## 1. Что посчитано

Явные запуски субагентов `subagent_type: general-purpose`: **780** (все с описанием). Категории назначались по ключевым словам описания, в порядке приоритета: BUILD, REVIEW, LOCATE, VERIFY, RESEARCH, OTHER. Правила эвристические.

| Категория по ключевым словам | Запусков | Доля |
|---|---|---|
| Ревью / аудит (REVIEW) | 117 | 15,0% |
| Проверка утверждений (VERIFY) | 105 | 13,5% |
| Поиск / локализация (LOCATE) | 61 | 7,8% |

Объект задачи (перекрывающиеся метки, сумма больше 100%):

## 2. Что это значит для плана

1. **C2 «локализация по кодовой базе» почти не отражает реальную работу.** Среди образцов категории LOCATE нет ни одного запроса по коду: это поиск механизмов, литературы и данных. Код встречается примерно в 15% запусков в целом, а не в одной категории.
2. **C1 «ревью артефакта» ближе к аудиту исследовательских материалов и стратегий,** чем к ревью кода с посеянными дефектами. Это влияет на внешнюю валидность: посеянные дефекты в исследовательских документах — возможно, но это другой объект.
3. **Самая крупная поддающаяся классификации группа — проверка утверждений (VERIFY, 13,5%).** Для неё в стеке есть узкий тип `verifier` (проверка утверждений на галлюцинации, без Write и Edit).
4. **Большая часть (55% по ключевым словам, 68,5% без объекта) не классифицируется.** Это главная неопределённость инвентаризации: эвристика не видит часть работы, и без расширенной проверки владельцем оценки категорий ненадёжны.

## 3. Предлагаемая замена (требует решения владельца)

| Вариант | Пары для пилота | Размер группы | Комментарий |
|---|---|---|---|
| А. Как одобрено | C1 ревью → `reviewer`; C2 локализация → `Explore` | C1: 117; C2: 61, но по образцам не по коду | Соответствует одобренному плану, но C2 не отражает реальную работу |
| Б. Рекомендуемый | C1 ревью → `reviewer`; **C3 проверка утверждений → `verifier`** | C1: 117; C3: 105 | Обе категории крупные; C3 заменяет C2 через поправку в журнале изменений плана |
| В. Расширенный | Б + C4 литература → `source-librarian` | C4: 45 | Меньше данных; тип сейчас в описании read-only, но в списке инструментов есть Write и Edit: проверить |

Позитивность (для варианта Б): `verifier` без Write и Edit; `reviewer` в среде имеет Write и Edit (смоук 2026-10-15; по файлу их нет). Задачи ревью и проверки не требуют записи файлов, поэтому позитивность выполняется в обоих толкованиях. Проверено шагом 3 фазы 0.

## 4. Что нужно от владельца

1. Проверить образцы из `phase0_samples_for_owner_review.md` (по 8 на категорию) и подтвердить, верны ли категории.
2. Выбрать вариант А, Б или В. Вариант Б или В — поправка журнала изменений плана до пилота.
3. Подтвердить, что оставшиеся шаги фазы 0 (определения агентов, хеши, банк задач) выполняются после этого решения.

## 5. Ограничения

- Классификация по ключевым словам: проверена на 8 образцах на категорию, не на всей выборке.
- Перекрытия между категориями и объектами не разрешены: метки считаются независимо.
- Число запусков относится к явным `general-purpose` за весь период транскриптов (2026-06-02 — 2026-10-15); состав задач мог меняться во времени.
