## L1 Attributes

**Population:** задачи из банка (bank_spec.md) в двух категориях: C1 — ревью документа с посеянными дефектами; C3 — проверка утверждений по двум источникам. Пилот: 8 задач (по 4 на категорию). Основной этап: n задач на категорию плюс резерв 20% на исключения. Включение: задача проходит проверку позитивности (обе группы могут её выполнить). Исключение: задача, которую одна из групп не может выполнить по набору инструментов; такие задачи учитываются отдельно.

**Intervention:** запуск субагентом узкого типа, сопоставленного категории: C1 → `reviewer`, C3 → `verifier`. Промпт задачи идентичен для обоих плеч; версия файла агента зафиксирована хэшем (positivity_versions.md); модель читается из транскрипта. Набор инструментов `reviewer` в среде совпадает с `general-purpose` (Write, Edit): узость типа — в роли и промпте.

**Comparator:** запуск явным `subagent_type: general-purpose` на той же задаче, с тем же промптом и моделью.

**Endpoint:**
- (а) C1 — доля найденных посеянных дефектов на запуск: найден 1, найден частично 0,5, не найден 0; слепая оценка по rubric.md.
- (б) C3 — доля проблемных утверждений с верным вердиктом: точный вердикт 1; признано проблемным, но вердикт другого типа 0,5; признано верным 0.
- (в) суммарные токены запуска (fresh input + cache creation + cache read + output) по уникальным `message.id` с максимумом по полям.

**Summary measure:** Δ_q — парная разность доли (узкий минус general) по задаче, абсолютная; отношение медиан токенов на запуск (узкий / general) — отдельно по категориям.

**MCID:** Δ_q ≥ −0,05 (non-inferiority; утверждено владельцем 2026-10-15); отношение медиан токенов ≤ 0,70 (снижение не менее 30%; утверждено 2026-10-15).

### Unmeasured Confounders

- **Утечка через отчёт:** стиль отчёта может выдать плечо (в прошлом эксперименте 2 из 10 задач). Смягчение: оценщик не видит имени агента; оба ответа задачи оцениваются одной партией в случайном порядке X/Y; калибровка.
- **Потолок контроля:** при контроле 0,94 эксперимент не различает плечи (прошлый опыт). Смягчение: пилот проверяет контроль ≤ 0,70; при превышении задача усложняется.
- **Состав задач:** выбор явного `general-purpose` в реальной работе не случаен. Смягчение: все задачи идут обоими плечами; вывод ограничен банком задач (см. «не означает»).
- **Вариация модели:** модель фиксируется алиасом и проверяется по транскрипту; запуски с другой моделью исключаются.
- **Рубрика с ожидаемыми вердиктами (C3):** оценщику передаётся ожидаемый вердикт, это необходимо для оценки. Смягчение: оценщик не получает фрагментов источников и не знает плеча.
- **Веб-инструменты:** у обоих плеч есть WebFetch и WebSearch; использование записывается как ковариата.

## What This Result Does NOT Mean

1. Не доказывает, что узкий тип работает на реальных задачах владельца: задачи синтетические.
2. Не сравнивает все типы агентов: только `reviewer` для C1 и `verifier` для C3.
3. Не даёт стоимость в деньгах: токены без тарифов.
4. Если результат «не отвергнут» (non-inferiority не доказано), не означает эквивалентность при меньшем числе задач, чем требуется.
5. Не моделирует, почему явный `general-purpose` выбирался в реальной работе.

## Sensitivity Analyses

1. **Альтернативная стратегия ICE:** исключить запуски с квотой или падением из обоих плеч (complete-case, while-active вместо treatment-policy).
2. **Альтернативный оценщик:** непарная оценка (Welch) и знаковый ранговый тест (Wilcoxon) вместо парного среднего; сравнивается устойчивость знака и ширины ДИ.
3. **Оценщик без одного грейдера:** пересчёт при отбрасывании каждого из двух слепых оценщиков (leave-one-grader-out).
