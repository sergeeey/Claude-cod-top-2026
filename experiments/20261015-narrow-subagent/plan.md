## 3. Фаза 1 — пилот

**Объём:** 8 задач × 2 плеча = 16 запусков. Калибровка: 2 пустых и 2 полных отчёта на каждого из двух оценщиков (без запусков агентов).

**Что измеряется:**
- доля найденных дефектов (C1) и доля проблемных утверждений с верным вердиктом (C3) по плечам — потолок контроля (ceiling.md);
- σ_d (разность по парам) с верхней границей 80% ДИ;
- токены и число шагов на запуск (порог токенов и оценка стоимости);
- доля сбоев по плечам (ICE);
- позитивность: доля задач, невыполнимых одним из плеч;
- согласие оценщиков.

**Ворота пилота:**

| Условие | Решение |
|---|---|
| Контроль ≤ 0,70 в каждой категории и калибровка пройдена | PROCEED: вычислить n по верхней границе σ_d |
| Контроль > 0,70 | задачи усложняются, пилот повторяется. Не свидетельство против claim (ceiling.md: `NO_HEADROOM`) |
| Калибровка провалена | STOP: `ORACLE_INADEQUATE`; рубрика исправляется, это не вывод |
| Позитивность нарушена для > 25% задач | категория или задачи пересматриваются |

## 4. Фаза 2 — основной этап

**n по правилу** (отдельно для каждой категории): n = ceil((z_{0,95} + z_{0,80}) · σ̂_d^{верх} / δ)², где σ̂_d^{верх} — верхняя граница 80% ДИ σ_d из пилота. Правило фиксируется до пилота.

Справочно при δ = 0,05 (проверено скриптом `mde_check.py`), на категорию: σ_d = 0,10 → 25 задач (50 запусков); σ_d = 0,15 → 56 (112); σ_d = 0,20 → 99 (198). По двум категориям: 100 / 224 / 396 запусков.

**Порядок:** каждая задача запускается обоими плечами, порядок и назначение рандомизированы. Параллельность не более 2. Оценка слепая, партиями, ответы X и Y в случайном порядке.

## 5. Фаза 3 — анализ и решение

**Primary:** парный бутстрап (10 000 повторов, фиксированный seed) для Δ_q и отношения медиан токенов; нижняя граница 95% ДИ; ICE = treatment-policy. Отдельно по каждой категории.

**Sensitivity (не менее 2 по правилу Full-Ladder):** complete-case; Welch и Wilcoxon; leave-one-grader-out.

**Решение (фиксируется до данных):**

| Условие | Решение (decision.md) |
|---|---|
| Нижняя граница Δ_q ≥ −δ И отношение медиан ≤ 0,70 в каждой категории | **REPLACE** для этой категории |
| Нижняя граница Δ_q < −δ в любой категории | **KEEP** explicit general-purpose |
| Качество в норме, отношение медиан > 0,70 | **KEEP**: смена не окупается |
| Нижняя граница внутри (−δ, 0), токены в норме | **REPEAT** с большим n; решение не принимается |
| Пилот или калибровка провалены | **BLOCKED**: не свидетельство против claim |

Отдельно записывается, на каких категориях и задачах решение действует. Вывод за пределами банка не делается.

## 6. Бюджет (порядок величины, не смета)

- Пилот: 16 запусков. Смоук `reviewer` (1 запуск) выполнен отдельно (A5). Фиксированная стоимость запуска субагента без работы: около 82 тыс. токенов.
- Основной этап: 100 / 224 / 396 запусков (обе категории) при σ_d 0,10 / 0,15 / 0,20.
- Токены: запуск × медиана токенов запуска. Реальная медиана явного `general-purpose` в транскриптах владельца — 2,0 млн на запуск (сессии с реальной работой). Грубо: 100 запусков ≈ 200 млн; 224 ≈ 450 млн; 396 ≈ 800 млн. **Оценка грубая; синтетические задачи, возможно, дешевле; пилот её заменит.**
