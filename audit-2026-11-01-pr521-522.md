## Findings and required fixes

### F1 — Compare the protocol with the actual freeze-commit blob

**HIGH, #522.** [CODE] [validate_experiment.py:440](https://github.com/sergeeey/Claude-cod-top-2026/blob/1490905da9fb9c19a4437d103eddbc871c4fde53/scripts/validate_experiment.py#L440) reads the current `claim.md`. Lines 462–478 find a commit by subject; line 480 reads only changed filenames. Line 551 compares the decision with the current threshold. Nothing loads the protocol contents at `freeze_sha`.

[VERIFIED-SYNTHETIC] Isolated repositories built with the shipped test fixture demonstrate two false accepts:

1. Freeze `>= 0.80`, commit results, then change both `claim.md` and `decision.md` to `>= 0.50` in a later commit. All seven frozen checks return **pass**.
2. Commit only a heading as `protocol(<id>): empty freeze`, commit the results, then fill the protocol and manifest. Again all seven checks return **pass**.

The unchanged valid control also passes. These are deterministic contract reproductions, not observed research misconduct or real-world incident rates. The template explicitly requires frozen values to remain unchanged and an amendment to use a new experiment ID.

**Fix:** Load `git show <freeze_sha>:<experiment>/claim.md`; parse the bounded Frozen Protocol section; require it to be complete at that commit; compare every frozen field with the current protocol, and compare the decision with the historical threshold. Reject changes under the same experiment ID. Add both negative cases above and a permitted amendment case. Git provides revision-qualified file retrieval separately from commit ancestry checks. [Official git-show documentation](https://git-scm.com/docs/git-show), [official git-merge-base documentation](https://git-scm.com/docs/git-merge-base).

### F2 — Bind the holdout hash to the freeze, not a mutable manifest

**HIGH, #522.** [CODE] [validate_experiment.py:535](https://github.com/sergeeey/Claude-cod-top-2026/blob/1490905da9fb9c19a4437d103eddbc871c4fde53/scripts/validate_experiment.py#L535) obtains the expected hash from today's manifest and compares it only with today's labels. The freeze commit's Holdout cell is merely checked for nonemptiness; even the valid test fixture contains no frozen hash there.

[VERIFIED-SYNTHETIC] After the fixture's results commit, change labels from `{"h1": 1}` to `{"h1": 0}`, update the manifest to the new SHA-256 and commit both. `check_frozen(exp, labels)` returns **pass for all seven checks**. Hashing works; the reference being hashed against is not anchored.

**Fix:** Require a valid SHA-256 in the immutable protocol, verify both the manifest and supplied labels against that value, and reject a holdout change under the existing experiment ID. Add a test that updates labels and manifest together. The CI command at [ci.yml:143](https://github.com/sergeeey/Claude-cod-top-2026/blob/1490905da9fb9c19a4437d103eddbc871c4fde53/.github/workflows/ci.yml#L143) supplies no `--labels`, so label verification is currently a warning there; disclose that limit and establish a separate evaluator-side check where labels must stay private.

### F3 — Check probability values elementwise

**MEDIUM, #522.** [CODE] [sci-code-audit/SKILL.md:157](https://github.com/sergeeey/Claude-cod-top-2026/blob/1490905da9fb9c19a4437d103eddbc871c4fde53/skills/extensions/sci-code-audit/SKILL.md#L157) teaches `assert 0 <= probabilities.all() <= 1`. For a numeric array, `.all()` produces a Boolean, so this range test passes regardless of the original numeric range.

[VERIFIED-SYNTHETIC] Executing the exact shipped assertion accepts `[-1, 0.5]`, `[0.5, 2]`, `[NaN]` and `[Infinity]`, as well as a valid control. The neighboring NaN check operates on `output`; it does not repair the range check and cannot reject finite −1 or 2. NumPy documents `all` as a truth-value reduction, not a range validator. [Official NumPy documentation](https://numpy.org/doc/stable/reference/generated/numpy.all.html).

**Fix:** Check finiteness and elementwise bounds, for example `np.isfinite(probabilities).all()` and `((probabilities >= 0) & (probabilities <= 1)).all()`. Define empty-array and normalization requirements separately. Exercise invalid values in a smoke test of this actual example.

### F4 — Preserve the requested alpha in correction decisions

**MEDIUM, #522.** [CODE] [hypothesis-red-team/references/traps.md:163](https://github.com/sergeeey/Claude-cod-top-2026/blob/1490905da9fb9c19a4437d103eddbc871c4fde53/skills/extensions/hypothesis-red-team/references/traps.md#L163) calls `multipletests(p_values, method=m)` inside `fwer_report(..., alpha=...)`. It uses the caller's alpha only for the uncorrected count and risk estimate.

[VERIFIED-SYNTHETIC] The exact example returns **one significant result** for each of Bonferroni, Holm, BH and BY for `p_values=[0.03], alpha=0.01`, while its own uncorrected count is zero. The library defaults to alpha 0.05. [Official statsmodels multipletests API](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html).

**Fix:** Pass `alpha=alpha` into `multipletests`; add a nondefault-alpha case that checks rejection decisions as well as corrected p-values. This is an executable example defect; no active research pipeline using it was established.

### F5 — Use real statsmodels power classes

**MEDIUM, #522.** [CODE] [hypothesis-red-team/references/traps.md:180](https://github.com/sergeeey/Claude-cod-top-2026/blob/1490905da9fb9c19a4437d103eddbc871c4fde53/skills/extensions/hypothesis-red-team/references/traps.md#L180) imports `TTestOneSamplePow, TTestIndPow`.

[VERIFIED] Extracting and executing that block raises `ImportError: cannot import name 'TTestOneSamplePow'`. This prevents the supplied `required_n` helper from becoming callable. The documented one-sample/paired class is `TTestPower`; the independent-sample class is `TTestIndPower`. [Official statsmodels power API](https://www.statsmodels.org/stable/generated/statsmodels.stats.power.TTestPower.html).

**Fix:** Correct the imports and constructors, validate the design argument, and execute a small example for both supported designs in CI. A Markdown code fence is still a shipped code path when the skill explicitly promises executable implementations.
