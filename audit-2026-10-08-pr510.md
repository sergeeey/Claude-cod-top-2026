## Findings and concrete fixes

### F1 — State the process boundary of the isolation

**LOW; confirmed limitation, not a newly introduced logging regression.** [CODE] [conftest.py lines 32–45](https://github.com/sergeeey/Claude-cod-top-2026/blob/8f1ea2e5a18373a59419a81596f7bb29ae9e712a/tests/conftest.py#L32) changes only the loaded `lib.state.HOOK_TRIGGERS_LOG` attribute. [state.py line 273](https://github.com/sergeeey/Claude-cod-top-2026/blob/8f1ea2e5a18373a59419a81596f7bb29ae9e712a/hooks/lib/state.py#L273) initializes the path from `Path.home()` when a fresh interpreter imports the module. The fixture does not alter inherited home variables or supply subprocess configuration.

[VERIFIED-SYNTHETIC] With the actual fixture active, launched the target `hooks/input_guard.py` in a child Python process with a synthetic injection input. The child denied the input and wrote one trigger to a deliberately fake home at `<probe tmp>/.claude/logs/hook_triggers.jsonl`, outside the parent's fixture-selected path. The probe never targeted the real user's home. This proves the process boundary, not an observed live pollution incident.

[CODE] Existing `tests/test_stdin_bom.py:42–52` already uses child hook processes and inherits home settings, but its inspected input-guard cases do not establish a trigger-log write. Do not count that test as a confirmed post-fix leak.

**Fix:** Qualify the docstring and PR claim as isolation of in-process hook calls. Before claiming all pytest-triggered writes are isolated, add a child-process regression and supply a temporary home in the relevant subprocess harness before imports, or introduce an explicit telemetry path override consumed by the logger. Merely exporting an unused environment variable would not fix this.

### F2 — Add a regression for the protection itself

**LOW; verification gap.** [CODE] The full diff adds the fixture but no assertion. `tests/test_hook_triggers_telemetry.py:20–28` independently patches the same attribute; `tests/test_log_rotation.py` also supplies its own log path. Passing those tests confirms compatibility with the fixture, not its isolation guarantee.

[VERIFIED-SYNTHETIC] Audit-only probes confirmed that two separate tests receive distinct clean log destinations, that an ordinary `log_hook_trigger()` call writes there, and that a later explicit override wins. These probes are audit artifacts and are not shipped regression coverage.

**Fix:** Add a regression that invokes the real logger without replacing its destination, checks that the destination is temporary and the home-based sentinel is untouched, and covers cleanup/next-test isolation. Test subprocess behavior separately. Do not assert only that a monkeypatch assignment took place.

## Security scan

- **Trust boundary:** synthetic test activity must stay out of operational telemetry. The sink is `lib.state.log_hook_trigger()` opening its destination for append.
- **Injection/deserialization:** the new fixture accepts no external payload and introduces no shell invocation, evaluation, deserialization or network call. The subprocess probe exercises existing guard behavior; it executes no payload command.
- **Secrets:** manual inspection and a limited scan of added lines found zero private-key header, AWS access-key, GitHub token or API-key pattern matches. This is not an exhaustive repository secret audit.
- **Races:** function-scoped fixture plus a freshly allocated directory avoids sharing a destination between ordinary tests. The patched attribute remains process-global; same-process background threads outliving fixture teardown were not tested. No new async code or confirmed race was found. Existing logger rotation concurrency limitations are outside this diff.
- **Paths and account actions:** paths are generated by the test temporary-directory factory, without user-controlled path concatenation. No account actions or rate-limited external API calls are introduced. F1 limits the reach of the protection.

## 🔥 Trend Gap

As checked on **2026-10-08**, official pytest documentation supports autouse fixtures in `conftest.py`, reversible `monkeypatch.setattr`, and temporary-directory fixtures. It also explains fixture ordering and restoration. This PR uses those established mechanisms appropriately for in-process calls. No evidence justifies claiming an industry-wide migration to a newer pattern. Sources: [pytest monkeypatch guide](https://docs.pytest.org/en/stable/how-to/monkeypatch.html), [pytest fixture reference](https://docs.pytest.org/en/stable/reference/fixtures.html).

The remaining gap is an explicit, tested boundary for isolation, rather than choice of an outdated tool.
