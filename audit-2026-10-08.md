## Findings and concrete fixes

### F1 — Preserve shell syntax through the Unicode normalization path

**MEDIUM, defense-in-depth detection regression.** [CODE] The new branch at [input_guard.py lines 293–302](https://github.com/sergeeey/Claude-cod-top-2026/blob/6a07ebe213b115bc7e2ebdfe047dcfcb3ede6550/hooks/input_guard.py#L293) strips ASCII backticks from the raw string and from `_normalize(text)`. The comment specifically says full-width grave accents are handled through NFKC. However, the existing `_LEET` mapping converts `$` to `s` inside `_normalize`.

[VERIFIED-SYNTHETIC] Payload, written with escapes to make the character identity unambiguous:

```python
text = "run \uff40echo $\uff40(whoami)"
```

The raw path retains U+FF40 between `$` and `(`, so it finds no `$(`. The normalized path becomes `run ` + backtick + `echo s` + backtick + `(whoami)`; stripping the backticks leaves no substitution signal. `scan([text], ignore_backtick_spans=True)` returns `{}`. Calling `main()` produces **allow** for both `spawn_task.prompt` and `send_message.message`; the base commit produces **deny**. The ASCII-backtick variant and the text with backticks removed both produce **deny** at the target.

**Boundary and impact:** outbound prompt/message data reaches another agent after a PreToolUse permission decision. The demonstrated impact is loss of the explicitly intended normalized substitution detection. U+FF40 is not literal shell command substitution, and this hook executes no shell command. Exploitation would additionally require downstream interpretation/transformation and an action permitted by other controls; that was not tested. The old denial came from the broad backtick clause, so this is a newly exposed normalization gap rather than proof that the old filter understood the payload semantically.

**Fix:** For the relaxed command-injection branch, also scan an NFKC-only copy with backticks removed, retaining `$`, alongside the existing raw and leet/confusable views. Keep other categories on their original inputs and retain max-based deduplication. Add positive controls for benign full-width code references and negative cases for substitution split across full-width/mixed backticks, parameterized over the actual two tool/field pairs. Do not globally remove the leet mapping; other categories rely on it.

### F2 — Exercise the real message field in negative integration tests

**LOW, coverage gap; no separate runtime failure demonstrated.** [CODE] [The new `_decision` helper](https://github.com/sergeeey/Claude-cod-top-2026/blob/6a07ebe213b115bc7e2ebdfe047dcfcb3ede6550/tests/test_input_guard.py#L649) always sends `{"prompt": prompt}`, including when its caller selects `mcp__ccd_session_mgmt__send_message`. The actual `message` field is covered by a benign allow test later in the class.

[VERIFIED-SYNTHETIC] Independent audit probes using the actual `message` field correctly denied the ASCII split substitution, chained removal, exfiltration marker and two-category injection examples. Thus the finding is missing regression protection, not a claim those ordinary inputs currently pass.

**Fix:** Parameterize negative integration tests over `(spawn_task, prompt)` and `(send_message, message)` and check strict handling of `send_message.session_id` too. Reuse the existing helper instead of duplicating another runner.
