## Findings and fixes

### F1 — Preserve the planned bound when recomputation would strengthen the null claim

**MEDIUM.** [CODE] The new block at [ab-test/SKILL.md:211](https://github.com/sergeeey/Claude-cod-top-2026/blob/00618654865a4a8827d9db4409eb78e72d69bd52/skills/extensions/ab-test/SKILL.md#L211) computes MDE only from observed `rate_c` and analyzed sample size. The new report line at [line 297](https://github.com/sergeeey/Claude-cod-top-2026/blob/00618654865a4a8827d9db4409eb78e72d69bd52/skills/extensions/ab-test/SKILL.md#L297) prints that value directly. There is no input or comparison for the planned MDE.

The referenced [estimand-ops rule 4](https://github.com/sergeeey/Claude-cod-top-2026/blob/00618654865a4a8827d9db4409eb78e72d69bd52/rules/estimand-ops.md#L194) requires keeping the larger planned bound when the observed-data recomputation is smaller. Its rule 1 requires reporting the design belonging to whichever bound is retained.

[VERIFIED-SYNTHETIC] With 10,000 observations per arm, alpha=0.05 and target power 0.80, planned baseline 0.5 gives upward MDE **0.019806**. Observed baseline 0.1 gives **0.012198**, which the actual new block reports. This strengthens the stated sensitivity from 1.98 to 1.22 percentage points after seeing outcomes, contrary to the project's declared rule. This is a synthetic arithmetic example, not an observed experiment.

**Fix:** Load the preregistered directional MDEs and their design parameters, compare them with recalculated values, and retain the weaker claim per direction. Preserve unavailable directions and keep the selected n/baseline/alpha attached to the selected bound. If planned detectability was never recorded, explicitly disclose that gap instead of implying compliance with the pre-data design rule. Add a case where the observed baseline lowers the calculated MDE.

### F2 — Use the analysis alpha in the new MDE

**MEDIUM.** [CODE] [Line 216](https://github.com/sergeeey/Claude-cod-top-2026/blob/00618654865a4a8827d9db4409eb78e72d69bd52/skills/extensions/ab-test/SKILL.md#L216) hardcodes alpha=0.05; the report repeats it. Yet [section 2e, line 233](https://github.com/sergeeey/Claude-cod-top-2026/blob/00618654865a4a8827d9db4409eb78e72d69bd52/skills/extensions/ab-test/SKILL.md#L233) requires alpha=0.05/(k−1) for multiple variants. Nothing restricts the new bound to a single unadjusted comparison.

[VERIFIED-SYNTHETIC] For five total arms/four control comparisons, 10,000 observations per arm and baseline 0.1:

| Quantity | Value |
|---|---:|
| MDE printed by the new code | 0.012198 |
| Required per-comparison alpha | 0.0125 |
| Power at that printed MDE under alpha=0.0125 | **0.619454** |
| Upward MDE for 80% power at alpha=0.0125 | **0.014608** |

The comparison deliberately uses the same NormalIndPower approximation throughout, isolating the alpha mismatch. The library exposes alpha as an explicit power-equation input. [Official statsmodels API](https://www.statsmodels.org/stable/generated/statsmodels.stats.power.NormalIndPower.solve_power.html).

**Impact:** The report overstates detectability for a supported multi-variant analysis. The older MCID power calculation already hardcodes alpha; this PR propagates that limitation into a newly claimed numerical null bound. It is not a newly introduced multiplicity bug in the old p-value calculation.

**Fix:** Determine the analysis family and correction before power/MDE calculations. Pass a shared effective alpha through the power calculation, MDE and report. For procedures without a single fixed per-comparison alpha, define a suitable conservative design calculation or state that the current bound does not apply. Add the four-comparison case above.

### F3 — Label or remove the equal-small-arm approximation

**LOW; conservative, not an inflated sensitivity claim.** [CODE] [Lines 215–216](https://github.com/sergeeey/Claude-cod-top-2026/blob/00618654865a4a8827d9db4409eb78e72d69bd52/skills/extensions/ab-test/SKILL.md#L215) set n to min(n_c,n_v) and ratio to 1.0. This models two groups of the smaller size rather than the analyzed allocation.

[VERIFIED-SYNTHETIC] At n_control=10,000, n_variant=1,000 and baseline=0.1, the new code gives upward MDE **0.040624**. Using the same approximation with nobs1=10,000 and ratio=0.1 gives **0.029561**. The default is conservative but is not the actual allocation's minimum detectable effect. [Official ratio semantics](https://www.statsmodels.org/stable/generated/statsmodels.stats.power.NormalIndPower.solve_power.html).

**Fix:** Use actual sample sizes via nobs1 and ratio, printing both sizes, or label the output explicitly as an equal-small-arm conservative approximation. The min(n) convention predates this PR in the power check; the new MDE inherits it.
