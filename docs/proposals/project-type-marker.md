# Предложение: явный маркер типа проекта для project_classifier

Адресат: сессия, которая ведёт автоматическое обнаружение проектов (`hooks/project_classifier.py`).
Статус: предложение. Код не менялся. Это не задача для пилота `deletion-test`.
Автор: сессия «Скиллы», 2026-11-25.

## Проблема (наблюдение с реального проекта)

1. `project_classifier.py` безусловно перезаписывает `.claude/memory/_auto/project_profile.md`
   при каждом старте сессии (`write_profile()`, строки около 305–340). [VERIFIED: чтение кода]
2. Явного способа задать тип вручную нет. Единственный намёк в файле: «Dispatcher / LLM may
   override», то есть решение остаётся на усмотрении модели в конкретной сессии. [VERIFIED]
3. В реальном исследовательском проекте хук присвоил тип `production`, хотя проект — `research`.
   От типа зависит подгрузка правил: EstimandOps, FL Full, skeptic или reviewer с покрытием
   тестов. Расхождение поймал скилл `dispatcher`, но его правка профиля не переживает
   следующий старт. [CONFLICTING: факт расхождения — из обратной связи пользователя;
   сам хук на этом проекте не запускался, веса не проверены]
4. В `tests/test_project_classifier.py` нет теста на переопределение. [VERIFIED: список тестов]

## Предлагаемое решение

Файл `.claude/project_type` в корне проекта (одна строка: `research | production | mvp |
data-science`). Правила:

| Ситуация | Что пишет хук в `project_profile.md` | Что говорит в контексте сессии |
|---|---|---|
| Файл есть и значение допустимо | `Type: <declared>`, строка `Declared by: .claude/project_type`, строка `Auto-detected: <auto> (margin=N)` | тип из файла, методология этого типа |
| Файл есть, значение недопустимо | как без файла, плюс предупреждение в контексте | автоматический тип с пометкой «файл проигнорирован» |
| Файла нет | как сейчас | как сейчас |

Авто-значение сохраняется всегда. Так расхождение видно и не теряется.

## Критерии приёмки (тесты, не описания)

1. Явный тип побеждает автоматический (тест: сигналы говорят `production`, файл говорит `research`,
   в профиле `Type: research`).
2. Авто-значение записано рядом (тест: в профиле есть строка `Auto-detected`).
3. Недопустимое значение не ломает сессию и не даёт тип (тест: `Type: unknown` → авто-тип + предупреждение).
4. Без файла поведение не меняется (тест на существующий `test_writes_profile_file` проходит без правок).
5. Файл маркера не коммитится в репозитории с чужими данными: решить, нужен ли `.gitignore`
   для `.claude/project_type` (это решение владельца).

## Что не входит в предложение

- Изменение весов ключевых слов. Это отдельная задача, её надо проверять на размеченных репо.
- Изменение скилла `dispatcher`. Его роль остаётся разовой проверкой, как и было сказано в обратной связи.
- Новые обязательные хуки. Изменяется существующий хук.

## Риски

- Ручной маркер может устареть: проект переходит из MVP в production, а файл не обновлён.
  Смягчение: хук пишет и авто-значение, расхождение видно в профиле.
- Ложная уверенность: тип из файла воспринимается как истина. Смягчение: в профиле явно
  указано, что это декларация владельца, а не проверка.
