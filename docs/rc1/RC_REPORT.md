# RC 1.0 — консолидированный отчёт

Дата: 2026-11-27. Кандидат: ветка `rc/1.0-candidate`, база `main` `34272be`. Точный SHA приёмки
указан в разделе 7. Ветка локальная, не опубликована.

**Итоговый статус: PARTIAL.** Инженерная часть кандидата (DoD-4) проверена в изоляции. DoD-1,
DoD-2 и DoD-3 подтверждены частично: разбором реальных задач и детерминированными тестами, но без
экспериментального сквозного прогона на новых задачах. DoD-5 выполнен в той форме, которую допускает
контракт без платных запусков: протокол готов, превосходство над обычным Claude Code не доказано.

## 1. Архитектура: исходная и итоговая

Исходная: цикл цели описан в конституции (v1 §4, v2 §4), но шаг Decide нигде не был явным, а контракт
миссии жил в тексте сессии и однажды был потерян при сжатии контекста (2026-11-26).

Итоговая — без нового агента и без нового маршрутизатора:

| Этап цикла | Чем обеспечен |
|---|---|
| Intent → Goal Contract | контракт миссии как Markdown-файл вне сжимаемого контекста (`docs/rc1/PROGRAM_CONTRACT.md` — пример) |
| Capability Discovery, Plan, Execute | основная сессия Claude Code: навыки, агенты, MCP, план задач среды |
| Verify | тесты, CI, независимые агенты-ревьюеры, privacy-guard, `regression_oracle.py` |
| Decide | **новое**: `scripts/goal_state.py` — явный вердикт DONE/CONTINUE/REPLAN/BLOCKED/STOPPED, DONE только с доказательствами по каждому критерию |
| Remember | состояние миссии на диске, журнал решений; память хуков — без изменений (заморозка) |
| Сохранение цели при восстановлении | **новое**: `goal_state.py check` — хеши разделов «Цель», «DoD», «Ограничения» |
| Интеграция с живой установкой | **новое**: `scripts/settings_overlay.py` — сохранение приватного слоя настроек |

Решение по Boyko (конституция v2 §14): функция оркестратора цели выполняется основной сессией.
Основание: задачи #578–#582 прошли весь цикл в основной сессии с внешними проверками (CI, ревьюеры,
Codex). Отдельный агент не нужен, пока не показано, что основная сессия теряет цель или выбирает
компетенции хуже. Для потери цели добавлено детерминированное обнаружение.

## 2. Дорожная карта (выбрана самостоятельно)

1. Контракт и состояние на диск. 2. Гейты целостности. 3. Изолированная установка, откат, проверка
неизменности live. 4. Решение по оркестратору цели. 5. Явный шаг Decide. 6. Протокол приёмки и
сравнения. 7. Отчёт. По ходу добавлен шаг: сохранение приватного слоя настроек — барьер, найденный
на шаге 3.

## 4. Отвергнутые решения и отрицательные результаты

- Отдельный агент-оркестратор Boyko: не создан, причина в разделе 1.
- Ветка `feat/goal-contracts`: не взята, это маршрутизация по контрактам (индекс на 8830 строк), а не цикл цели.
- `install.sh --force-replace` для живого обновления: отвергнут, теряет приватный слой.
- Обычный неинтерактивный `install.sh` для обновления: отвергнут как единственный шаг, не применяет новую разводку.
- Слияние навыка `boyko-goal-compass` (#544): отложено, навыки заморожены, проверка дрейфа там — суждение модели.
- Перенос знаний по похожим словам: 0 из 3 случаев; лексический поиск опыта признан недостаточным (N06).

## 5. Ограничения

1. Эффект на долю решённых задач не измерен: нет разрешённых модельных запусков и достаточного held-out.
2. Применение найденного знания моделью не проверено.
3. `goal_state.py` не встроен в рабочий цикл автоматически: им нужно пользоваться явно.
4. После интеграции 19 UNPROVEN-файлов останутся живыми версиями, конфигурация не будет равна проверенной.
