# RC 1.0 — процедура независимой приёмки

Критерии заданы до получения результатов. Приёмку может провести человек или агент без доступа к
истории этой сессии: все шаги — команды с ожидаемым результатом.

## 1. Идентичность кандидата

Кандидат — ветка `rc/1.0-candidate` (локальная, без push). База: `main` = `34272be`. Поверх базы
только `docs/rc1/` и `scripts/goal_state.py` с тестами. Точный SHA приёмки фиксируется в отчёте
(`git -C <worktree> rev-parse HEAD`); приёмка на другом SHA недействительна.

Что входит в ядро RC: всё, что ставит `install.sh --profile=standard` из этого дерева. Что не входит:
файлы, существующие только в живой установке владельца (`hooks/lib/git_commands.py`,
`hooks/pre_push_privacy_guard.py`, `hooks/entity_prereader.py` и 19 файлов класса UNPROVEN). Ядро от
них не зависит: хуки ядра используют свои версии из репозитория.

## 3. Функциональная приёмка цикла цели (DoD-1, DoD-2)

Без платных запусков проверяется только то, что не требует модели:
- явный шаг Decide и запрет DONE без доказательств по каждому критерию (T7);
- обнаружение тихого изменения цели при восстановлении: правка разделов «Цель», «DoD» или
  «Ограничения» контракта даёт `goal_state.py check` exit 1 (тест `test_goal_edit_is_drift`).

Сквозной прогон цикла на новой задаче с независимой проверкой требует модельных запусков и пока не
разрешён. До него DoD-1 подтверждается только разбором уже выполненных задач (см. отчёт RC), то есть
описательно, а не экспериментально.

## 4. Сравнение с обычным Claude Code (DoD-5)

Метод, состояния результата, обязательные «защитные» метрики и дисциплина held-out заданы в
`tests/eval/e2e-regression-set.md` и здесь не дублируются.

Вопрос (L0): **причинный**. Вмешательство — конфигурация. Сравнение: кандидат RC против обычного
Claude Code без надстройки (`--bare` отключает хуки и навыки; либо пустой изолированный каталог
конфигурации). Одна модель, одинаковые задачи, бюджет и права, порядок запусков случайный, минимум
3 запуска на задачу и конфигурацию, оценка оракулом `scripts/regression_oracle.py` и независимым
проверяющим.

Оценивается: доля подтверждённых задач (основная), вмешательства владельца, время и токены на
подтверждённый результат, регрессии, накладные расходы контекста.

Обнаруживаемость: `n, baseline_or_sigma, alpha, power, MDE, MCID` = 5 задач на конфигурацию
(независимые единицы — задачи, а не запуски), базовая доля 0.5 (допущение, источника нет),
0.05 двусторонний, 0.8, MDE=undetectable, MCID 0.2 (решение владельца не записано, это предложение).
При 5 задачах никакое различие не обнаружимо, поэтому любой результат будет «uninformative at this n»,
а не «нет эффекта». Для обнаружения разницы 0.5 → 0.2 нужно около 39 независимых задач на
конфигурацию.

Состояние: **превосходство RC над обычным Claude Code не доказано.** Платные запуски не разрешены;
публичные задачи C1–C5 не являются held-out; приватный пул held-out недостаточен по размеру.
