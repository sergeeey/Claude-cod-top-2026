## Findings and concrete fixes

### F1 — Application path overrides escape benchmark isolation

**HIGH; #516.** [CODE] [scripts/bench_hooks.py:211](https://github.com/sergeeey/Claude-cod-top-2026/blob/1f5af7a764789bf98c33c92a261762b6967bb58d/scripts/bench_hooks.py#L211) copies the entire parent environment and changes only HOME/USERPROFILE/APPDATA/LOCALAPPDATA plus encoding and recursion settings. It retains `CLAUDE_HOME` and `CLAUDE_CONFIG_DIR`. The registered `resource_router.py` resolves those variables before `Path.home()` and appends to `logs/router_predictions.jsonl` (`hooks/resource_router.py:110–161`).

[VERIFIED-SYNTHETIC] For each override separately, ran the actual target resource router with the benchmark's representative UserPromptSubmit payload and `make_env()` output. Both exited 0 and wrote to a separate **fake live directory**, outside the fake benchmark home. No real user log or credential was used. The precondition is an inherited application override; actual historical live-log contamination was not investigated.

**Impact:** synthetic benchmark activity can alter operational telemetry despite the explicit isolation promise. **Fix:** redirect both application overrides into the isolated home, audit other inherited write/network configuration, and add a sentinel test using the real router subprocess. Preserve only required environment inputs or explicitly document the remaining boundary. Environment rewriting is not an OS sandbox.

### F2 — Wrapped hooks are never executed

**MEDIUM; #516.** [CODE] [resolve_command at scripts/bench_hooks.py:127](https://github.com/sergeeey/Claude-cod-top-2026/blob/1f5af7a764789bf98c33c92a261762b6967bb58d/scripts/bench_hooks.py#L127) substitutes `__PYTHON_CMD__` only at argv position zero. All six `async_wrapper.py` commands in the real manifest also contain an inner interpreter placeholder. It remains literal. The existing wrapper attempts that executable, catches the resulting launch failure and exits 0.

[VERIFIED-SYNTHETIC] The actual wrapper returned 0 while a synthetic child did not create its sentinel. Directly running that same child created the sentinel successfully. [VERIFIED] All six resolved manifest commands retain the inner placeholder; they cover post-format, GitNexus reindex, pattern extraction, session save, raw-to-wiki and webhook notification.

**Impact:** timings and the 134-command flag-equivalence statement include wrapper successes that establish nothing about their child hooks. **Fix:** resolve interpreter placeholders at every command position, including interpreter flags; test child execution explicitly. Separate wrapper launch overhead from child completion and behavior. Apply the risky-hook exclusion to the inner command before enabling execution: `script_name()` currently sees only `async_wrapper.py`, and `verify_flags()` does not apply `SKIP_BY_DEFAULT` at all. Do not fix the placeholder and inadvertently start network hooks during routine verification.

### F4 — Identical launch failures pass flag verification

**MEDIUM; #516.** [CODE] [scripts/bench_hooks.py:481–531](https://github.com/sergeeey/Claude-cod-top-2026/blob/1f5af7a764789bf98c33c92a261762b6967bb58d/scripts/bench_hooks.py#L481) compares `(returncode, stdout, stderr)` triples but never establishes successful launch of the intended hook. [VERIFIED-SYNTHETIC] A manifest naming `does-not-exist.py` produced `verified 1 hook commands`, `mismatches caused by the flag: 0`, exit 0. **Fix:** validate resolved executable/script arguments before running; distinguish interpreter launch failures from legitimate hook decisions such as intentional exit 2; report execution failures separately and fail verification on them. ## Security scan

- **Trust boundaries:** installer environment → command template; benchmark environment/manifest → subprocesses and filesystem; live JSON settings → advisory path-existence output.
- **Injection:** installer exact-token allowlists reject code-selecting flags and shell syntax. Benchmark subprocess calls use argv lists, not a shell. A caller-supplied manifest is executable configuration and must be trusted; this audit did not execute untrusted commands. No new SQL/deserialization execution sink was found.
- **Secrets:** limited scan of all added lines found zero private-key header, AWS access-key, GitHub-token or API-token pattern matches. Values were not printed. This is not an exhaustive historical secret audit.
- **Filesystem:** F1 is reproduced. Space-sensitive command parsing is F4. The drift checker inspects settings-derived paths without executing them. No permission changes were made.
- **Concurrency:** benchmark variants/groups share a temporary workdir/home and session ID. State can accumulate or contend across concurrent hooks; group subprocess outcomes are discarded. The committed `commit_test_gate.py` rows include both 0 and 2, showing mixed observed behavior, but not proving a race. No concrete lost-update race was reproduced. A/B state independence and child lifetime need tests after F2.
- **Network/rate limiting:** the declared default risky-hook exclusion does not identify wrapped children, and the verifier has no equivalent exclusion. Existing unresolved placeholders suppress those child launches in the shipped manifest; that incidental failure is not a safety control. No external webhook, package manager or notification was invoked during this audit.

## 🔥 Trend Gap

Checked official sources on **2026-10-14**. CPython 3.11 documents `-S` as disabling automatic `site` processing, `-s` as excluding user site packages and `-B` as preventing bytecode writes. The installer allowlist reflects these semantics. This does not establish that every installed hook branch is compatible with `-S`. [Python command-line reference](https://docs.python.org/3.11/using/cmdline.html).

Claude Code documents parallel matching hooks and asynchronous execution. Measuring grouped subprocess latency is relevant, but the actual child command and lifecycle must match the registered hook. The documented harness exclusion remains appropriate. [Claude Code hooks reference](https://code.claude.com/docs/en/hooks).

pyperf documents warmups, environmental jitter and reproducible benchmarking. The PR adopts useful practices, especially alternating variants, but retains only per-hook summaries and misses execution-validity checks. The immediate gap is trustworthy measurement and isolation, not a need to adopt a fashionable dependency. No evidence supports an assertion that the industry migrated to a new pattern this month. [pyperf benchmark guidance](https://pyperf.readthedocs.io/en/latest/run_benchmark.html).
