## Findings and concrete fixes

### F1 — A nearby quotation becomes the current study's verdict

**MEDIUM; #533; [CODE], [VERIFIED-SYNTHETIC].** At [build_research_catalog.py:118](https://github.com/sergeeey/Claude-cod-top-2026/blob/c29067567aecd67096ef44ad5601e4622af73113/scripts/build_research_catalog.py#L118), `_corrected_verdict` searches the first 40 lines for any correction marker and any downgrade/revision pair. It does not establish that the statement belongs to the current decision or exclude quotations. `parse_verdict` then gives this match precedence over an explicit checked verdict.

Minimal input:

```markdown
# decision - current study
## Verdict
- [x] REJECT

## Related work
> Earlier study verdict downgraded CONFIRMED -> WEAKENED.
```

The base returns `REJECT`; the target returns `WEAKENED` and `has_correction=True`. Moving the same quotation beyond line 40 returns `REJECT`. This shows the location cutoff does not establish ownership. No production incident or frequency estimate is claimed.

**Fix:** Bind correction extraction to an explicitly scoped correction section/field for this decision; exclude quoted and fenced reference material. Preserve the governing verdict or mark ambiguous correction state for review if ownership cannot be established. Add this short-document negative control alongside the existing far-below-header control. Retain the successful own-correction case.

### F2 — An earlier correction hides the later governing revision

**MEDIUM; #533; [CODE], [VERIFIED-SYNTHETIC].** At [build_research_catalog.py:122](https://github.com/sergeeey/Claude-cod-top-2026/blob/c29067567aecd67096ef44ad5601e4622af73113/scripts/build_research_catalog.py#L122), `_CORRECTED_TO.search(head)` returns the first matching correction.

The probe contains two explicitly dated addenda within the first 40 lines: November 1 downgrades `CONFIRMED -> WEAKENED`; November 2 revises `WEAKENED -> FALSIFIED`; the original checked `CONFIRMED` remains below. The target returns `WEAKENED`, despite the explicit later `FALSIFIED` revision. The base returned `CONFIRMED`, so this is a new feature's incomplete correction handling, not a claim that the old version handled it correctly.

**Fix:** Define how the authoritative correction is selected, using explicit revision/supersession metadata where available. Do not simply switch to the last arbitrary regex match: quotations would still be unsafe. When several corrections cannot be ordered reliably, expose ambiguity instead of presenting one as settled. Test chronological and newest-first arrangements, plus unresolved conflicts.

## 🔥 Trend Gap

Checked 2026-11-03 against primary guidance. The meaningful gap is authority separation, not the absence of a newer graph/vector tool. OWASP recommends keeping trusted instructions separate from untrusted content and enforcing action permissions at tool boundaries; prompt wording alone is not an enforcement boundary. The skill's prose guards are useful but are not a tested security sandbox. F1 illustrates the analogous evidence problem: nearby text is not necessarily governing evidence. [OWASP LLM Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html).

Python's regex documentation confirms that `search` returns the first match; it supplies no revision-order semantics. F2 therefore needs an explicit authority/ordering contract, not a library upgrade. [Python regular-expression documentation](https://docs.python.org/3/library/re.html#re.search).

**Automate this:** correction-parser review → add a small checked-in boundary matrix covering own/quoted corrections, two revision orders, ambiguous revisions and branch-only records → estimated 10–15 minutes/week if these changes recur weekly; estimate, not measured savings. Keep baseline and treatment inputs for skill scenarios before building larger evaluation infrastructure.
