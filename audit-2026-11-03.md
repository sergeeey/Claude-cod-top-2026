## Findings and required fixes

Line numbers refer to target commit `1cca98467d87634f75c2bea38a6fae1f1a73a818`. Reproductions are **[VERIFIED-SYNTHETIC]**: temporary Git repositories exercise actual target code, not observed data-loss incidents or frequency estimates.

### F1 — A tracked folder is not a committed decision

**MEDIUM, #528.** [CODE] [build_research_catalog.py:243](https://github.com/sergeeey/Claude-cod-top-2026/blob/1cca98467d87634f75c2bea38a6fae1f1a73a818/scripts/build_research_catalog.py#L243) runs `git ls-files -- .` over the entire experiment directory, then assigns `COMMITTED_BRANCH` when its decision is absent from default. The fallback at line 250 also checks directory history rather than decision history.

[VERIFIED-SYNTHETIC] Commit `protocol.md`, then create an untracked `decision.md`: catalog state is `COMMITTED_BRANCH`, while `git log --all -- <decision>` is empty. The health hook correctly flags this particular case. Staging a fresh experiment without committing also yields `COMMITTED_BRANCH`. A result appears preserved although its decision is in no commit.

**Fix:** Base capture state on the exact decision file in reachable commits, independently of index membership and sibling files. Keep `UNCOMMITTED_ORPHAN` if no decision commit exists. If showing a dirty current verdict alongside historical capture state, expose that distinction. Add protocol-only and staged-only catalog cases. Git documents `ls-files` as an index/worktree listing, not commit evidence. [Official git-ls-files documentation](https://git-scm.com/docs/git-ls-files).

### F2 — Staging must not silence the capture warning

**MEDIUM, #529.** [CODE] [research_health_loop.py:165](https://github.com/sergeeey/Claude-cod-top-2026/blob/1cca98467d87634f75c2bea38a6fae1f1a73a818/hooks/research_health_loop.py#L165) enumerates only `ls-files --others --exclude-standard`. Newly staged decisions are absent from that list, so their missing history is never checked.

[VERIFIED-SYNTHETIC] A fresh decision yields one warning. After `git add experiments`, with no commit, warnings become empty and decision history remains empty. This contradicts the message “decision.md not committed to any branch.”

**Fix:** Include staged additions as candidates, then check exact decision history. Test untracked → staged → committed, expecting a warning in the first two states. Retain the intentional ignore policy unless separately changed.

### F3 — Parse machine-safe Git paths

**MEDIUM, #528/#529.** [CODE] The health hook splits newline output at lines 168–170. [build_research_catalog.py:277](https://github.com/sergeeey/Claude-cod-top-2026/blob/1cca98467d87634f75c2bea38a6fae1f1a73a818/scripts/build_research_catalog.py#L277) applies a terminal `.md` regex to `ls-tree --name-only` lines. Neither handles Git quoting.

[VERIFIED-SYNTHETIC] With `core.quotePath=true`, untracked `experiments/20261103-тест/decision.md` yields no warning. Commit it on a side branch and check out main: branch-only catalog discovery returns no record. Git emits escaped UTF-8 bytes inside quotes; the trailing quote defeats both parsers. Existing ASCII fixtures exercise successful ordinary paths.

**Fix:** Use `-z` for filename output, split on NUL and decode explicitly. Audit worktree-path parsing separately. Add Cyrillic and quoted-path tests to both suites. Git documents quoting without `-z`. [Official git-ls-files documentation](https://git-scm.com/docs/git-ls-files.html), [official git-worktree documentation](https://git-scm.com/docs/git-worktree.html).

### F4 — Do not discard experiments based on words in their IDs

**MEDIUM, #528.** [CODE] `_is_copy` in `scripts/build_research_catalog.py` tests whether any copy marker occurs anywhere in the relative path. `snapshot`, `backup` and `phase4` are unbounded substrings.

[VERIFIED-SYNTHETIC] A normal experiment at `experiments/20261103-snapshot-retrieval/decision.md` yields an empty catalog. It is not inside a copy directory. Legitimate research can silently disappear from the view intended to prevent duplicate work.

**Fix:** Exclude explicit directory components or configured copy roots, rather than words in experiment IDs. Add a legitimate ID containing `snapshot` and a genuine snapshot-copy directory as opposing controls.

### F5 — Preserve the complete verdict token

**MEDIUM, #528.** [CODE] `_CHECKED` at [build_research_catalog.py:57](https://github.com/sergeeey/Claude-cod-top-2026/blob/1cca98467d87634f75c2bea38a6fae1f1a73a818/scripts/build_research_catalog.py#L57) has no end-of-token constraint and runs before the custom-token parser. `_LABELLED` has the same prefix problem.

[VERIFIED-SYNTHETIC] `## Verdict\n- [x] REJECTED_WITH_LIMITATIONS` returns `REJECT`, contradicting the promise “as written, never mapped.” Existing custom-verdict tests use tokens without known-verdict prefixes.

**Fix:** Extract the whole token first, preserve it, and classify separately if needed. Alternatively reject continuation characters, including underscores/hyphens, after a known token. Test suffixed known verdicts in checked and labelled forms.

### F6 — Check checkout lag independently of snapshot lag

**LOW, #525.** [CODE] [session_start.py:639](https://github.com/sergeeey/Claude-cod-top-2026/blob/1cca98467d87634f75c2bea38a6fae1f1a73a818/hooks/session_start.py#L639) checks `HEAD..origin/main` only when origin was selected as ahead of the recorded snapshot.

[VERIFIED-SYNTHETIC] Memory records current main/origin; HEAD is detached at its parent. `HEAD..origin/main` is one commit, but `snapshot_staleness` returns `None`. Memory is current; the separately promised checkout warning is missing.

**Fix:** Calculate checkout lag independently whenever `origin/main` exists. Add a current-memory/stale-checkout fixture; do not label the current snapshot itself stale.
