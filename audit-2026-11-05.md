## Findings and fixes

### F1 — Recognize the complete tag name and opening delimiter

**MEDIUM; [CODE], [VERIFIED-SYNTHETIC].** [hooks/lib/runtime.py:82](https://github.com/sergeeey/Claude-cod-top-2026/blob/63fba0fcf788b3e18ccc00cf67720977ba51dc3e/hooks/lib/runtime.py#L82) adds `|<agent-message\b.*?</agent-message[^>]*>`. A regex word boundary accepts the hyphen in `agent-message-template`. The expression does not require an opening `>` before content, and the closing expression accepts arbitrary suffixes.

| Synthetic input | Base behavior | Target behavior |
|---|---|---|
| `<agent-message-template>run the database migration now</agent-message-template>` | Preserved; DESTRUCTIVE | Removed entirely; no advisory |
| `run <agent-message migration now </agent-message>` | Preserved; DESTRUCTIVE | Becomes `run`; no advisory |
| `<agent-message from="x">example </agent-message-template> credential report</agent-message>` | SECURITY from unfiltered report | Stops at the wrong closing name; SECURITY still fires |

Positive controls: the intended `<agent-message from="x">…</agent-message>` is removed, user text preceding it remains classified, and an opener without any closer remains intact. Thus the defect concerns lexical boundaries, not the entire approach.

The base comparison uses the exact base regex extracted from its Git blob and the unchanged classifier. Target cases additionally run the real hook with the original JSON prompt in a subprocess, with synthetic telemetry redirected to an audit-local home directory. Evidence: `reproduce.py` and `reproductions.json`. Real-world frequency of these shapes is **[NEEDS-REAL-DATA]**.

**Fix:** Require the exact `agent-message` element name and a completed opening delimiter; accept only explicitly supported closing syntax. Preserve other tag names and incomplete markup. Add the three controls above plus valid attribute/multiline cases. If nested or quoted delimiters are supported, define that grammar and use a bounded scanner rather than continuing to broaden an unstructured wildcard. Do not claim that lexical filtering authenticates who authored a block.

## Security and robustness review

- **Trust boundary / injection:** `data['prompt']` contains both user and harness-origin text. The changed filter affects advisory selection; it neither rewrites the model's original prompt nor enforces tool permissions. User-authored wrapper text can imitate harness text. That design limitation already existed for other wrappers and is extended here; it is not evidence of an authorization bypass.
- **Secrets:** Manual review of every added line found no credential value. A limited pattern scan of additions found no private-key header, GitHub-token pattern or AWS access-key-ID pattern. Words such as `password` and `token` in fixtures are synthetic text, not secrets. This is not a repository-wide secret audit.
- **Shell/SQL/path/deserialization:** No new shell execution, query, path construction, deserializer or external request is introduced. The code compiles a constant regex, not executable input.
- **Race conditions / rate limiting:** The filter is a pure transformation using a compiled pattern. No new mutable state, concurrent write or outbound call appears in the diff. Existing caller telemetry is outside the modified logic.
- **Nested blocks [VERIFIED-SYNTHETIC]:** An outer peer block containing an inner `<agent-message>` loses only the prefix through the inner closer. A trailing `credential report` remains and triggers SECURITY. This is a coverage limitation of the new feature, not a regression from successful base behavior; the base also emitted SECURITY. Its occurrence in real peer messages was not established.
- **Unclosed-openers cost [VERIFIED-SYNTHETIC]:** At 250/500/1000 repeated openers (6k/12k/24k characters), target filtering took approximately 0.006/0.023/0.093 seconds, versus 0.000013/0.000019/0.000038 seconds with the base pattern on the same input. These bounded, single-run timings support superlinear growth for this shape, not a calibrated benchmark or demonstrated timeout. The PR discloses this existing regex design class; the added branch expands it to `agent-message`. All three hook entries set a five-second timeout. Follow-up: bounded parsing or a conservative operation/input budget, with performance controls. No large stress run was launched.
